Design a Verilog module named `WordGame` that solves the word game problem for fixed N=8.

Module Parameters:
- N = 8 (number of letters)
- HALF_N = 4 (number of letters each player gets)

Inputs:
- clk: clock signal (rising edge triggered)
- rst_n: active-low synchronous reset
- start: start pulse (assert for one cycle to begin computation)
- arr_0, arr_1, ..., arr_7: 8-bit ASCII codes of the input letters (index 0 is leftmost)

Outputs:
- win: 1-bit, high if Slavko can win (i.e., there exists a strategy where his word is lexicographically smaller than Mirko's)
- word_0, word_1, word_2, word_3: 8-bit ASCII codes of Slavko's most beautiful word (lexicographically smallest possible)
- done: 1-bit, asserted for one cycle when computation is complete

Behavior:
The module should compute the optimal strategy for Slavko.

Algorithm (high-level):
1. When start is asserted, reset internal state and begin computation.
2. The module should consider all possible sequences of Slavko's picks (since Mirko's moves are deterministic given Slavko's picks). For N=8, there are at most 7*5*3*1 = 105 possible play sequences.
3. For each possible sequence, simulate the game:
   - Maintain a bitmask of remaining letters (8 bits).
   - For each round i from 1 to 4:
     a. Mirko picks the rightmost remaining letter (the highest index bit set in the mask). Remove it.
     b. Slavko picks one of the remaining letters according to the sequence.
   - At the end, construct Slavko's word (sequence of his picks) and Mirko's word (sequence of Mirko's picks).
4. Among all sequences, find the lexicographically smallest Slavko's word. That is the output `word`.
5. Also, determine if there exists any sequence where Slavko's word is strictly less than Mirko's word. If yes, set `win` high.
6. The computation may take multiple cycles; when finished, assert `done` for one cycle.

Implementation Notes:
- The module should be combinational with respect to the input letters; it may use a state machine to iterate through the 105 possibilities.
- Use a finite number of cycles per possibility (e.g., one cycle per possibility).
- When done, the outputs `win` and `word` are valid.
- On reset, all internal state is cleared, and outputs are zero.

Timing:
- After start, the module should assert done within 1000 clock cycles.
- The module should not rely on any external memory.

Testbench will be provided to verify correctness.
