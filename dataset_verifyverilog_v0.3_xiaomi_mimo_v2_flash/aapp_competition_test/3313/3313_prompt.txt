Design a Verilog HDL module named 'gem_collector' for the racing game gem collection problem.

PROBLEM: Given n gems at (x,y), vertical velocity v, horizontal velocity between -v/r and v/r, find maximum gems collectible.

SCALED CONSTRAINTS:
- n ≤ 16 (4-bit input)
- r ≤ 10 (4-bit input)
- Coordinates ≤ 65535 (16-bit)
- Result ≤ 16 gems (8-bit output)
- Max cycles: 200

INTERFACE:
Inputs:
  clk (1 bit) : Clock, rising edge
  rst_n (1 bit) : Active-low reset
  start (1 bit) : Start pulse (1 cycle)
  n [3:0] : Number of gems (1-16)
  r [3:0] : Ratio (1-10)
  w [15:0] : Track width
  h [15:0] : Finish height
  x [0:15][15:0] : X coordinates array
  y [0:15][15:0] : Y coordinates array

Outputs:
  result [7:0] : Maximum gems collectible
  done (1 bit) : Done signal (1 cycle)

IMPLEMENTATION REQUIREMENTS:
1. State Machine: IDLE → SORT → DP_INIT → DP_LOOP → FIND_MAX → DONE
2. Sort gems by y using bubble sort
3. DP algorithm: For each gem i, check all j < i for reachability
4. Reachability: r * |x[i]-x[j]| ≤ y[i]-y[j]
5. Result = max(dp array)
6. Must complete within 200 cycles

INTERNAL ARCHITECTURE:
- sorted_x, sorted_y: 16×16 bit registers
- dp: 16×8 bit registers
- Counters: i, j (4-bit)
- Temp registers for diffs and multiplication
- No external memories/FIFOs

CRITICAL OPERATIONS:
- Absolute diff: |x[i]-x[j]| = (x[i]>=x[j]) ? x[i]-x[j] : x[j]-x[i]
- Multiplication: r * |x_diff| (r ≤ 10, fits 20-bit)
- Comparison: (y[i]-y[j]) >= (r * |x_diff|)

RESET: All registers clear, done=0, result=0
START: Pulse high for 1 cycle to begin
DONE: Assert for 1 cycle when complete
