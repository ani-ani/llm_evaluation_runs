Design a Verilog module named "project_invites" that solves a simplified version of the invitation problem.
Input constraints: max 8 teams, employee IDs in 0-31 (5-bit). Stockholm IDs: 0-15 (friend=9), London IDs: 16-31.

Module interface:
module project_invites(
  input clk,               // clock
  input rst_n,             // active-low reset
  input start,             // start processing
  input [2:0] num_teams,   // number of teams (1-8)
  input [7:0][4:0] teams_i,// 8 team entries (each 5-bit ID1, 5-bit ID2)
  output reg [2:0] k,      // number of invitees (0-8)
  output reg [7:0][4:0] invitees,  // invitee list
  output reg done          // high when result ready
);

Behavior description:
1. On reset, all outputs zeroed. When start is asserted:
2. Implement simplified greedy algorithm: Iterate through teams, covering each team by either keeping current invitees
   or adding one new employee. Prioritize covering teams by selecting employee that covers most uncovered teams.
3. Always prefer selecting friend (ID=9) if equally optimal.
4. Process teams sequentially over 8 clock cycles maximum.
5. Output 'k' should be minimal invitee count. 'invitees' array should contain selected IDs (padded with 0s).
6. Assert 'done' after processing completes (8 cycles or when all teams covered).
