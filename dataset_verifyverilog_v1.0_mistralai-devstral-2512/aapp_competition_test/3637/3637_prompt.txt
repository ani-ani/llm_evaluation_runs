Implement a Verilog module that solves the pizza topping selection problem. Given N friends (1≤N≤10000) and T toppings (≤250), each friend has W_i wishes (1≤W_i≤30) of form +topping or -topping. Need to output a subset of toppings such that for each friend, strictly more than 1/3 of their wishes are fulfilled. Assume a solution exists where all friends have ≥2/3 wishes fulfilled.

Module Interface:
- Inputs:
  clk: clock signal
  rst_n: active-low synchronous reset
  start: 1-cycle pulse to start processing
  valid: 1 when input data is valid
  data_type: 1-bit (0=new friend, 1=wish)
  topping_idx: 8-bit (for data_type=0: contains W_i, for data_type=1: topping index)
  want: 1-bit (0=doesn't want topping, 1=wants topping)
- Outputs:
  done: 1-cycle pulse when complete
  result: 256-bit bitmask representing selected toppings (bit i=1 if topping i selected)

Implementation Strategy:
1. Use a 2-pass approach: First pass counts total wishes per topping to estimate popularity.
2. Second pass greedily selects toppings to maximize satisfaction.
3. For each topping, evaluate two scenarios: include vs exclude.
4. Track satisfaction count per friend and total wishes per friend.
5. After processing all toppings, output the selected set.

Constraints:
- Process each wish in 2-3 clock cycles
- Maximum 250 toppings × 10000 friends × 30 wishes = 75M wish entries, but input is stream
- Use internal memory: friend_satisfied[0:9999] (10k 6-bit counters), friend_total[0:9999] (10k 6-bit counters)
- Use 256-bit register for selected_toppings
- State machine with states: IDLE, LOAD, COMPUTE, OUTPUT
- Timing: start->done within 1000 cycles

Reset: done=0, result=0, all internal counters zeroed
