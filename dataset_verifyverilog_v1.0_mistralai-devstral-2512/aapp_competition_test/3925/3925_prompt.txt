You are to implement a digital circuit module in Verilog HDL that solves the "Zebra" problem.

**Problem Description:**
Given a binary string `s` consisting of characters 'b' (black) and 'w' (white), we can perform an operation any number of times: split the string at some position into two parts, reverse both parts, and concatenate them. This effectively allows us to rearrange the string arbitrarily into any cyclic rotation of the original string (or its reverse). The goal is to find the maximum length of a contiguous substring of alternating characters (a "zebra").

Since the operations allow cyclic shifts, we can treat the string as circular. The longest alternating sequence in a circular binary string is found by examining the string `s + s` (concatenated with itself) to handle the wrap-around. The maximum possible zebra length cannot exceed the length of the original string `n`.

**Hardware Implementation Strategy:**
1.  **Input:** The input string `s` is provided as a stream of bits. Let 'b' be mapped to `1` and 'w' to `0` (or vice versa, consistent mapping).
2.  **Logic:** We need to find the longest sequence where consecutive bits are not equal.
3.  **Scaling:** Since the input string length $|s|$ can be up to 100,000, we cannot store the entire string in FPGA block RAM if we use a naive approach. However, for benchmarking LLMs, we must scale the problem down to fit hardware constraints. 
    *   **Constraint:** We will support a maximum string length $N = 64$.
    *   **Storage:** The string will be stored in a BRAM of depth 64 and width 1 bit (or 8 bits for ASCII, but bit-packed is better). Alternatively, for a streaming interface, we process the input as it arrives.
4.  **Streaming Approach (Preferred for HDL):**
    *   The module receives the string bits one by one on a serial input `data_in` with a valid signal `data_valid`.
    *   We need to detect runs of alternating bits.
    *   To handle the circular nature (wrap-around from end to start), we need to know the first bit and the last bit.
    *   Since we receive bits serially, we can store the first bit in a register. We calculate the length of the alternating run from the start (prefix) and the length of the alternating run from the end (suffix). If the first and last bits differ, the total length is prefix + suffix, capped at $N$.
    *   **Buffer:** We need to store at least the suffix of the string to compare with the prefix. Since $N=64$, we need a buffer of 64 bits.
    *   **Control:** A control FSM will manage the serial input, calculate the alternating lengths, and compute the final maximum.

**Module Interface Specification:**
*   **Clock Domain:** Synchronous to `clk`.
*   **Reset:** Active-low synchronous `rst_n`.
*   **Inputs:**
    *   `clk`: System clock.
    *   `rst_n`: Active low reset.
    *   `start`: 1-cycle pulse to start processing a new string.
    *   `data_in`: 1-bit serial data input (representing the next character of the string).
    *   `data_valid`: 1-bit signal indicating `data_in` is valid.
    *   `len_in`: 6-bit input indicating the length of the current string (valid when `start` is high). Supports lengths up to 64.
*   **Outputs:**
    *   `result`: 7-bit output (maximum zebra length, max 64).
    *   `done`: 1-bit signal asserted for 1 cycle when calculation is complete.

**Algorithm Steps (FSM states):**
1.  **IDLE:** Wait for `start`. Capture `len_in`. Reset counters.
2.  **RECV:** Read `data_in` serially. Store bits in a buffer (FIFO or RAM). Track the current alternating run length from the start (prefix length). Store the first bit.
3.  **CALC:** Once all bits are received, compute the suffix length by scanning the buffer backwards. 
    *   If the first bit != last bit, result = prefix_len + suffix_len.
    *   Else, result = max(prefix_len, suffix_len).
    *   Cap result at `len_in`.
4.  **DONE:** Output result and assert `done`.

**Verilog Requirements:**
*   Use non-blocking assignments for sequential logic.
*   Ensure the buffer size is parameterized (e.g., parameter MAX_LEN = 64).
*   The solution must be purely combinatorial/sequential logic; no external memory or dynamic allocation.

**Hardware Adaptation for `s+s` logic:**
We process the input stream `s`. We need to detect alternating runs. We need to handle the "join" between the end of the stream and the beginning (for the `s+s` logic).
Since we process serially, we can:
1. Store the stream in a buffer (FIFO/RAM) of size `N` (64 bits).
2. Track the current alternating run length.
3. If the run breaks, check if we can wrap around using the buffer.

Simpler approach for LLM benchmark:
1.  **Input:** Serial stream of bits `s` of length `N`. 
2.  **Logic:** We want to find the longest alternating sequence in `s` (circularly).
    *   We scan `s` and compute `run_lengths` for alternating segments.
    *   Store `s` in a buffer.
    *   Compute prefix alternating length from start.
    *   Compute suffix alternating length from end.
    *   If first bit != last bit, result = prefix + suffix.
    *   Else, result = max(prefix, suffix).
    *   Also, we must track the max alternating run *inside* the string (not wrapping around).
    *   Final result is `min(max_inner_run, prefix+suffix_circular)`.
    *   Wait, the `s+s` logic is more robust. It simply finds the longest alternating run in the doubled string. This automatically handles the wrap-around as the run can span the boundary.

**Refined Logic for Hardware:**
1.  **Buffer:** Store the entire input string `s` (up to 64 bits) in a shift register or RAM.
2.  **Processing:**
    *   Read `s` and compute the longest alternating run in `s` (linear scan). Store this as `max_linear`.
    *   Read `s` again (or use the buffer) to compute the prefix alternating run length (`prefix_len`) starting from index 0.
    *   Read `s` backwards to compute the suffix alternating run length (`suffix_len`) ending at index `len-1`.
    *   Check if `s[0] != s[len-1]`.
    *   If they differ, `circular_len = prefix_len + suffix_len`. Else `circular_len = max(prefix_len, suffix_len)`.
    *   Result = `max(max_linear, circular_len)`.
    *   Cap result at `len`.

In hardware:
1. Buffer `s` of length `N`.
2. Iterate `i` from 0 to `2*N - 1`. `idx = i % N`.
3. Keep track of current run length. Compare `s[idx]` with `s[(idx-1)%N]`. If different, increment. If same, reset.
4. Update max.

This requires a counter for `2*N` iterations (max 128). This fits easily in an FSM.

**FSM States:**
- IDLE
- RECV (read `s` into buffer)
- SCAN (iterate 0 to 2*N, compute max alternating run)
- DONE

This is a clean, bounded hardware solution.
