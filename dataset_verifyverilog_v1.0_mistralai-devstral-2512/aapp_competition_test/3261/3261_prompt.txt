Design a Verilog module `hedgehog_grey` that simulates the grey cell counting on a fixed 16x16 grid for up to 256 steps. The hedgehog traverses cells in a zig-zag pattern starting at (0,0).

**Inputs:**
- `clk`: System clock, rising edge.
- `rst_n`: Active-low synchronous reset.
- `start`: 1-cycle pulse to start the computation.
- `row_limit[3:0]`: Max row index (0-15). 16 means full 16 rows.
- `col_limit[3:0]`: Max column index (0-15). 16 means full 16 columns.
- `k[15:0]`: Number of steps to take (up to 256).

**Outputs:**
- `result[15:0]`: Count of grey cells visited.
- `done`: 1-cycle pulse indicating computation finished.

**Grey Cell Logic:**
A cell at `(r, c)` is grey if `(r & c) == 0`. White otherwise.

**Traversal Logic:**
Traverse a `row_limit` x `col_limit` grid (conceptually 0-indexed up to limit-1).
Traversal order:
1. Row 0: Left to Right (0 -> col_limit-1)
2. Row 1: Right to Left (col_limit-1 -> 0)
3. Row 2: Left to Right
... and so on.

**Implementation Details:**
1. Implement a counter for current step `step_cnt` (0 to `k-1`).
2. Maintain current coordinates `r`, `c`.
3. Maintain direction flag `dir` (0=Left->Right, 1=Right->Left).
4. On each step, check `if ((r & c) == 0)` then increment `result`.
5. Update `(r, c)` and `dir` for the next step according to zig-zag rules.
6. Stop when `step_cnt` reaches `k`. Assert `done` for 1 cycle.

**Constraints:**
- Use combinational logic for coordinate updates.
- FSM to handle start, processing, and done states.
- All inputs are registered on `clk`.
- `k` is the limiting factor (up to 256). Grid size limits the domain.
