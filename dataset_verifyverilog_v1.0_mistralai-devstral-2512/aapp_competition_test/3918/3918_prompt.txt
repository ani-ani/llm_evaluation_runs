Design a Verilog module to minimize array error after exactly k1+k2 operations.

**Core Algorithm:**
1. Compute absolute differences d[i] = |A[i] - B[i]|
2. For each operation (total K = k1+k2):
   - Find index 'idx' where d[idx] is maximum (priority encoder)
   - Decrement d[idx] by 1 (if d[idx] > 0), else set d[idx] = 1
3. Compute result = sum(d[i] * d[i])

**Interface (Ports):**
- Inputs:
  - `clk`, `rst_n`: Standard synchronous control
  - `start`: 1-cycle pulse to initiate computation
  - `A_in`, `B_in`: 8x8-bit arrays (n=8, values -256 to 255). Signed integers.
  - `K_in`: 9-bit integer (0 to 256), representing k1+k2.
- Outputs:
  - `result`: 32-bit unsigned integer (maximum possible error)
  - `done`: 1-cycle pulse indicating valid result

**Implementation Requirements:**
1. **State Machine:** Synchronize on `clk` using `rst_n` (active low).
2. **Array Storage:** Store 8 differences d[7:0] in registers (8-bit unsigned).
3. **Operation Logic:** Iterate K times (K provided at start):
   - In each iteration, use a priority reduction loop (cascaded comparators) to find the index of the maximum value in d[7:0].
   - Decrement the selected d[i] by 1. If it reaches 0, it stays 0 (or cycles to 1, then decrements next time; see logic below).
   - *Optimization Note:* Since we want to minimize sum of squares, decrementing the largest difference is always optimal. If max is 0, changing it to 1 (and 0 in next step) creates unnecessary oscillation. The standard solution is: if max_diff > 0, decrement it. If max_diff == 0, it must have been 0 and remains 0 (or increments to 1 if we must use the operation, but 0->1->0 is suboptimal for sum of squares). However, problem statement implies exactly k ops. If all diffs are 0, any operation increases one diff to 1. 
   - *Refined Logic:* 
     - Find max_val and its index.
     - If max_val > 0: new_val = max_val - 1
     - If max_val == 0: new_val = 1 (we are forced to use the operation, increasing error from 0 to 1).
4. **Summation:** After K operations, compute d[i]^2 for each i (using 8x8 multiplier) and sum them (8 sums of 16-bit -> 19-bit, fits in 32-bit).
5. **Timing:** 
   - Input latency: 1 cycle (sample A, B, K).
   - Computation: K cycles (K max 256) + 1 cycle for summing.
   - Total latency < 300 cycles.

**Signal Widths:**
- A_in/B_in: 8-bit signed (mapped from -256 to 255 via scaling factor).
- d array: 8-bit unsigned (0-255).
- K counter: 9-bit (0-256).
- Multiplier: 8x8 -> 16-bit.
- Accumulator: 32-bit.

**Testbench Expectations:**
- Scale inputs to fit 8-bit signed range.
- Verify result matches Python logic on scaled inputs.
