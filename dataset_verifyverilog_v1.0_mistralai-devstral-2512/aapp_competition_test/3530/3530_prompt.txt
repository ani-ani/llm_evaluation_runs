You need to implement a dynamic programming module that maximizes total fun given time constraints.

**Core Problem**: Given N roller coasters, each with fun coefficients a_i, b_i and ride time t_i. The fun on the k-th ride is f(i,k) = a_i - (k-1)^2 * b_i. We need to answer Q queries for different total times T.

**Adaptation for Hardware**:
1. Scale N to maximum 8 coasters
2. Scale Q to maximum 8 queries
3. Scale T to maximum 255 minutes (8-bit)
4. Scale t_i to maximum 255 (8-bit)
5. Scale fun values to 16-bit signed
6. Simplify fun calculation: Use linear approximation for first 8 rides per coaster (k-1)^2 for k<=8
7. Maximum total rides per coaster limited to 8
8. DP state: dp[time] = max fun achievable

**Module Interface**:
- Inputs:
  - clk: system clock, rising edge active
  - rst_n: active-low synchronous reset
  - start: 1-cycle pulse to start computation
  - N: 4-bit, number of coasters (1-8)
  - Query_T: 8-bit, total time budget for current query
  - For each coaster i (0 to 7):
    - a_i: 16-bit signed, fun coefficient
    - b_i: 16-bit signed, decay coefficient  
    - t_i: 8-bit unsigned, ride time
  - Query_Index: 3-bit, current query index (0-7)
- Outputs:
  - result: 16-bit signed, maximum fun for current query
  - done: 1-cycle pulse, valid when computation complete
  - busy: high while computing

**Implementation Requirements**:
1. Use iterative DP approach with unbounded knapsack variant
2. For each coaster, precompute fun values for up to 8 rides: fun_ride[i][k] = a_i - (k-1)^2 * b_i
3. Only consider rides where fun > 0
4. DP updates: For each time t from 0 to Query_T, for each coaster i, for each possible ride count k (1-8), if t >= k*t_i and fun > 0: dp[t] = max(dp[t], dp[t-k*t_i] + k*fun)
5. Pipeline state updates with 1-cycle latency
6. All arrays stored in registers (no dynamic allocation)
7. Clock frequency: 100MHz (10ns period)
8. Maximum computation time: 256 cycles per query
9. Reset values: dp[0..255] = 0, result = 0, done = 0
10. Fixed-point arithmetic for fun calculations (no floating point)

**Timing**:
- start pulse initiates computation for current query
- done pulse asserts exactly 1 cycle after computation completes
- result remains valid until next query or reset
- busy signal remains high during computation

**Constraints**:
- All parameters and values fit in specified bit widths
- Use 2's complement for signed arithmetic
- No division operations
- No conditionals that can't be converted to muxes
