Implement a Verilog module that calculates the minimum number of badge decks Vasya needs to take.

**Problem Logic:**
Given integers `b` (boys), `g` (girls), and `n` (participants).
A deck with `i` blue badges (boys) and `n-i` red badges (girls) is suitable if:
1. `i <= b` (we have enough boys to take blue badges)
2. `n - i <= g` (we have enough girls to take red badges)

We need to count the number of valid integers `i` in the range `[0, n]` satisfying these conditions.
This simplifies to finding the size of the intersection:
- `i` must be `>= 0` and `<= n`
- `i` must be `<= b`
- `i` must be `>= n - g`

The valid range for `i` is:
- Lower bound: `L = max(0, n - g)`
- Upper bound: `U = min(n, b)`
- Count: `max(0, U - L + 1)`

**Module Interface:**
- **Inputs:**
  - `b` (8-bit unsigned): Number of boys (max 300)
  - `g` (8-bit unsigned): Number of girls (max 300)
  - `n` (8-bit unsigned): Number of participants (max 600)
- **Output:**
  - `result` (10-bit unsigned): The calculated minimum number of decks.

**Implementation Details:**
1. Calculate `n_minus_g = n - g`. Since this can be negative, treat it as signed logic or clamp to 0.
   - Intermediate value `lower_bound = (n > g) ? (n - g) : 0;`
2. Calculate `upper_bound = (b < n) ? b : n;`
3. Calculate `diff = upper_bound - lower_bound`.
4. If `diff` is negative, `result` is 0. Otherwise, `result = diff + 1`.
   - Note: Since we are working with unsigned integers, subtraction might wrap. It's safer to check if `upper_bound < lower_bound` first.

**Constraints:**
- `b`, `g`, `n` <= 300 (fits in 9 bits, use 16 bits for safety).
- Result max is `n+1` <= 601 (fits in 10 bits, use 16 bits for safety).
- Combinational logic only (no clock/reset needed).
