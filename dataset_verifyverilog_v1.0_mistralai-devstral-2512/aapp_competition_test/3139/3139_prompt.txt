Design a Verilog module that simulates the student helper matching logic for a maximum of N=16 students. Students arrive with 2D coordinates (A, B). A query 'P i' asks: find the student j (j != i) such that A_j >= A_i and B_j >= B_i (dominance). Among those, minimize (B_j - B_i), then minimize (A_j - A_i). If no such student, output NE (or index 0).

Module Interface:
- Inputs: `clk` (1-bit), `rst_n` (1-bit, active low). `start` (1-bit, 1-cycle pulse).
- Data In: `op_type` (1-bit, 0=Add student, 1=Query). `idx` (4-bit, for Query). `A_in`, `B_in` (16-bit each, for Add).
- Outputs: `result_idx` (4-bit, 0 for NE, valid when done=1). `done` (1-bit, 1-cycle pulse). `valid` (1-bit, indicates if result is valid).

Implementation Details:
1. Storage: Maintain arrays `A_mem[0:15]`, `B_mem[0:15]` (16-bit wide) and a valid bitmask `students_present` (16-bit).
2. Logic: 
   - On `start` and `op_type==0`: Store A_in and B_in in the first available slot (indexed by `students_present` count). Update count.
   - On `start` and `op_type==1`: Perform a linear search over all valid students. For each student `j` (where `students_present[j]==1` and `j != idx-1`), check dominance: `A_mem[j] >= A_query` AND `B_mem[j] >= B_query`. 
   - Keep track of the best student found so far based on the criteria. Since N is small (16), this is feasible in hardware.
3. Timing: 
   - Add operation: 1 cycle.
   - Query operation: Max 16 cycles (one comparison per cycle using a state machine).
   - `done` pulses 1 cycle after query completes or immediately after add.
4. Constraints: 
   - Use 16-bit widths for A/B.
   - Use 4-bit indices (1-16).
   - Handle invalid queries (index > current count) by outputting NE (result_idx=0).
