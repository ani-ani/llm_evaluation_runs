Design a Verilog module that finds the time with minimum digit changes from an input broken time to a valid time in either 12-hour or 24-hour format.

### Interface Specification:
- **Inputs:**
  - `clk`: Global clock (rising edge)
  - `rst_n`: Active-low synchronous reset
  - `start`: 1-cycle pulse to initiate computation
  - `format`: 1-bit signal (0 for 24-hour, 1 for 12-hour)
  - `broken_h1`, `broken_h0`: 4-bit digits for hours tens and ones (0-9)
  - `broken_m1`, `broken_m0`: 4-bit digits for minutes tens and ones (0-9)

- **Outputs:**
  - `correct_h1`, `correct_h0`: 4-bit digits for hours tens and ones (0-9)
  - `correct_m1`, `correct_m0`: 4-bit digits for minutes tens and ones (0-9)
  - `done`: 1-cycle pulse indicating valid output ready

### Functional Requirements:
1. **Initialization (State 0):** Wait for `start` pulse. On `start`, reset internal counters and valid flag.
2. **Computation (States 1-3):**
   - Iterate through all valid hours (0-23 for 24h, 1-12 for 12h) and valid minutes (0-59).
   - For each candidate time (candidate_h, candidate_m):
     - Compare each of the 4 digits (h_tens, h_ones, m_tens, m_ones) with the corresponding broken digit.
     - Count the number of mismatches (Hamming distance).
   - Track the candidate with the minimum number of mismatches found so far.
3. **Output (State 4):** Once all valid times are checked (24*60=1440 or 12*60=720 iterations), output the best matching time as the four 4-bit digit outputs and pulse `done` for 1 cycle.
4. **Reset:** When `rst_n` is low, set `done=0`, outputs to 0, and return to State 0.

### Timing & Constraints:
- **Clock Speed:** Assume 100 MHz (10ns period).
- **Latency:** Must complete within 2000 cycles (max 20µs for 24h format).
- **Data Widths:** All digits are 4-bit (0-9). Internal counters for hours (5-bit) and minutes (6-bit). Mismatch counter needs 4 bits (max 4 digits).
- **Storage:** Internal registers to hold `best_h`, `best_m`, `best_error`.
- **Digits to Number Conversion:** The input digits `h1,h0` represent the integer `h1*10 + h0`. Similarly for minutes. The module must extract these from the broken time and compare digit-by-digit against the generated candidate digits.

### Implementation Notes:
- Use a Finite State Machine (FSM) with states: IDLE, SETUP_H, SETUP_M, COMPARE, UPDATE, OUTPUT.
- Use a loop-like counter structure (iterative) for hours and minutes to avoid large combinational logic.
- When `format=1` (12-hour), skip hour 0.
- When generating candidate digits, ensure `h_tens` and `h_ones` are valid (e.g., 01, 09, 12).
- The comparison logic should compute: `error = (candidate_h1 != broken_h1) + (candidate_h0 != broken_h0) + (candidate_m1 != broken_m1) + (candidate_m0 != broken_m0)`.
- Use `always @(posedge clk or negedge rst_n)` for all sequential logic.

### Example Flow:
Input: format=0 (24h), broken=99:99 (digits 9,9,9,9).
1. Check hour 00 (digits 0,0): errors = 2 (h) + 2 (m) = 4. Best error=4, best time=00:00.
2. Check hour 01 (digits 0,1): errors = 1+1+2 = 4. Best error=4.
3. ... continue until hour 09 (digits 0,9): errors = 1+0+2 = 3. Best error=3, best time=09:00.
4. Check minute 01 (digits 0,1): errors = 1+0+2+1 = 4.
5. Check minute 09 (digits 0,9): errors = 1+0+1+0 = 2. Best error=2, best time=09:09.
6. Output 09:09.
