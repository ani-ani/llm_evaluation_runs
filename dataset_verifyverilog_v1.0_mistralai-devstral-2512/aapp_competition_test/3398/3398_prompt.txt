Algorithm:
1. Input: Up to 16 icons. Each has (r, c) 16-bit, and type (1=delete, 0=keep).
2. We need to find a rectangle R (min_r, max_r, min_c, max_c) such that:
   - All 'delete' icons are inside R (their centers).
   - No 'keep' icons are inside R.
   - This rectangle must be valid (max_r > min_r, max_c > min_c).
3. We want to minimize the number of icons (delete or keep) that are NOT already in R (i.e., must be moved INTO R to be grouped, or moved OUT so they don't block R).
   - Actually, the problem implies moving icons to group the 'delete' ones. We can move icons anywhere on screen (valid positions).
   - To achieve 1 delete operation, we need a rectangle containing all 'delete' icons and NO 'keep' icons.
   - We can move icons. Moving a 'delete' icon usually means moving it into the rectangle. Moving a 'keep' icon usually means moving it out of the rectangle.
   - Cost = number of icons moved.
   - Minimizing cost is equivalent to maximizing the number of icons that stay in place (are already valid in the optimal rectangle).
   - Icons that stay: 'delete' icons already inside R + 'keep' icons already outside R.
