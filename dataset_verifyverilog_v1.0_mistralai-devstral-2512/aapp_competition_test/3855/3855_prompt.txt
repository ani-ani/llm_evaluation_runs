Design a Verilog module that computes the bit length (number of bits) of a given input number n, which represents the minimum number of packets needed for the coin problem. For n=6, answer is 3; for n=2, answer is 2. The core algorithm is: count how many bits are needed to represent n in binary, i.e., floor(log2(n)) + 1.

Interface Specification:
- Inputs:
  - clk: Clock signal, rising edge triggered
  - rst_n: Active-low synchronous reset
  - start: 1-cycle pulse to start computation
  - n[29:0]: Input number, maximum value 10^9 (fits in 30 bits)
- Outputs:
  - result[4:0]: Output result (maximum 30, fits in 5 bits)
  - done: 1-cycle pulse indicating result is valid

Timing Requirements:
- Start to done: Within 100 cycles for all inputs
- Reset: 2 cycles minimum, result=0, done=0
- Computation should be iterative (subtract or shift based) to avoid large multipliers

Implementation Constraints:
- Use only 32-bit arithmetic (or smaller)
- No floating point operations
- Simple state machine with loop counter
- Max clock cycles: 256

Hint: The answer is simply the number of bits required to represent n in binary. For example, n=6 (binary 110) requires 3 bits, n=2 (binary 10) requires 2 bits. Can implement by repeatedly dividing by 2 until zero, counting iterations.
