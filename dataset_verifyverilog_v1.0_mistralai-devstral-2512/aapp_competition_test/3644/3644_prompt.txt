## Verilog Module Specification: HR Staff Optimization

### Problem Summary
Simulate workforce hiring/firing over n days with LIFO firing constraint. Determine minimum HR people needed and assign IDs to daily operations (hiring + firing).

### Core Logic (Simplified)
1. **Worker Stack**: Each worker has an ID (hired day + offset). Simulated as a LIFO stack of 16-bit values (16 nodes max).
2. **Firing LIFO**: When firing f workers, must pop f IDs from stack (last hired first).
3. **Hiring**: Push h new IDs onto stack (ID = day_index * 256 + offset).
4. **HR Assignment**: For each day, the HR person must differ from the HR person who hired any worker being fired. Track HR IDs for each worker ID.
5. **Minimization**: Find minimum k (≤8) and assign HR IDs (1..k) sequentially, ensuring no conflict with fired workers' hire-HR-ID.

### Interface
- **Clock/Reset**: `clk` (posedge), `rst_n` (active-low sync)
- **Inputs**: 
  - `f_i` [7:0]: workers fired on day i (max 255)
  - `h_i` [7:0]: workers hired on day i (max 255)
  - `start`: start processing (1-cycle pulse)
  - `day_index` [3:0]: current day (0 to n-1, n≤16)
- **Outputs**:
  - `hr_id` [7:0]: HR person ID for this day (1-based)
  - `min_hr_k` [3:0]: minimum HR people needed
  - `done`: completion flag (1-cycle pulse)
  - `stack_overflow` [1:0]: error flag (0=ok)

### Timing
- `start`→`done` within 100 cycles
- `rst_n` must assert for min 2 cycles
- After `rst_n`=1, `done`=0, `hr_id`=0, `min_hr_k`=0

### Constraints
- `n` ≤ 16 days
- `f_i`, `h_i` ≤ 255 (8-bit)
- Total workers ≤ 4096 (stack depth)
- Worker ID: 16-bit {day[7:0], idx[7:0]}
- HR ID: 4-bit (1..8)
- Stack max depth: 512 entries (FIFO/LIFO simulation)

### Algorithm Steps (Hardware)
1. **Day Processing Loop** (FSM)
   - S0: Idle, wait for start
   - S1: Load day parameters (f_i, h_i)
   - S2: Pop f_i workers from stack, record hire-HR-ID
   - S3: Assign HR ID for today (avoid conflicts with popped IDs)
   - S4: Push h_i new workers onto stack
   - S5: Update min_hr_k, done

2. **Stack Implementation**
   - 512 x 16-bit register array
   - Pointer: stack_top [8:0] (0 to 511)
   - Operations: push (stack[stack_top++] = id), pop (id = stack[--stack_top])

3. **Conflict Resolution**
   - Maintain conflict_flag [7:0]: bits for HR IDs 1..8 (set if conflict)
   - For each popped worker: set conflict_bit = hire_hr_id
   - Choose smallest HR ID not in conflict set
   - Reset conflict set after day

4. **Min k Tracking**
   - max_k [3:0] tracks max HR ID used
   - After each day: max_k = max(max_k, assigned_hr_id)
   - Output final max_k

### Implementation Notes
- Use 16-bit data path for worker IDs
- 8-bit for f_i/h_i
- 4-bit for HR IDs (1..8)
- Maximum 16 days, 256 ops/day
- Stack simulation via sequential array write
- No recursive calls, all loops bounded by day count
