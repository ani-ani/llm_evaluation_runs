Implement a Verilog module that finds a point belonging to at least (n-1) rectangles. Given n rectangles (n ≤ 16), each with 4 coordinates (x1,y1,x2,y2) in range [-1000,1000], find any integer point (x,y) that is inside at least n-1 rectangles.

Algorithm:
1. Compute prefix intersections: prefix[i] = intersection of rectangles 0 to i-1
2. Compute suffix intersections: suffix[i] = intersection of rectangles i+1 to n-1
3. For each i, check if prefix[i] ∩ suffix[i] is valid (non-empty). If yes, output (x1,y1) of that intersection.
4. Coordinates are scaled by 1000 to fit 16-bit signed range [-1000000,1000000]

Interface:
Inputs:
  clk: clock
  rst_n: active-low async reset
  start: 1-cycle pulse to start
  n: 4-bit (1-16)
  rect_x1[0:15]: 16x16-bit signed array
  rect_y1[0:15]: 16x16-bit signed array
  rect_x2[0:15]: 16x16-bit signed array
  rect_y2[0:15]: 16x16-bit signed array
Outputs:
  result_x: 16-bit signed
  result_y: 16-bit signed
  done: 1-cycle pulse when valid

Timing: start->done within 300 cycles
Reset: done=0, result=0, min 2 cycles

Internal: Use 32-bit for intermediate computations to prevent overflow during intersection.

Key constraints:
- Intersection of rectangles [a,b,c,d] and [e,f,g,h] is [max(a,e), max(b,f), min(c,g), min(d,h)]
- Valid if max(a,e) <= min(c,g) and max(b,f) <= min(d,h)
- When found, output (max(a,e), max(b,f))
- Use scaled coordinates: original_coord * 1000 to fit in 16-bit signed
- All operations must complete within 300 cycles
- Use parametrized loops with max 16 iterations
- No dynamic memory - use fixed-size arrays
- Overflow protection: clamp intermediate results to 32-bit signed range
