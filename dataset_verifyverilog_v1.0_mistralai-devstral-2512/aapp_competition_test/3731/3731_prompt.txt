Implement a Verilog module that calculates the minimum number of distinct letters in substring s[l:r] generated by the game.

**Problem Analysis:**
The string s is generated in cycles. Each cycle consists of Mister B appending b letters (arbitrary choices) followed by the computer appending a letters. The key observation is that the computer's algorithm creates a periodic pattern. For optimal results, Mister B forces a cycle of length 2a+2b with a specific letter distribution.

**Constraints & Scales:**
1. a, b are small (1 to 12).
2. l and r are up to 10^9, so simulation is impossible. We must use the mathematical periodicity.
3. The problem reduces to finding the number of distinct letters in a segment of a pre-computed periodic sequence.
4. The periodic sequence length is `Period = 2 * (a + b)`.
5. The alphabet size is limited to `a + 1`.

**Module Interface:**
- Inputs:
  - `clk`: System clock (rising edge).
  - `rst_n`: Active-low reset.
  - `start`: 1-cycle pulse to start calculation.
  - `a_in`: 4-bit unsigned (1-12).
  - `b_in`: 4-bit unsigned (1-12).
  - `l_in`: 32-bit unsigned.
  - `r_in`: 32-bit unsigned.
- Outputs:
  - `result`: 8-bit unsigned (max distinct letters is a+1 ≤ 13, fits in 8 bits).
  - `done`: 1-cycle pulse indicating result is valid.

**Implementation Logic:**
1. **Pre-computation Phase (Setup):** The module should contain logic to generate the periodic sequence for the given `a` and `b`.
   - Sequence generation logic (can be a combinational block or a small FSM).
   - The sequence is of length `Period`. Store it in a register array or ROM.
   - Sequence Generation Rules (derived from optimal strategies):
     - If `b >= a`: Sequence length is `2a + 2b`. The pattern involves repeating blocks and shifting values to minimize distinct counts.
     - If `b < a`: Similar logic but with slight variations in the suffix.
     - *Simplification for HW:* Construct a lookup table (LUT) in Verilog that maps inputs (a, b, index_in_period) to the letter ID. Since a,b ≤ 12, `Period ≤ 48`. We can compute this on the fly or store a compressed representation.

2. **Query Processing Phase (Calculation):**
   - Normalize `l` and `r` relative to the period.
   - `l_norm = ((l - 1) % Period) + 1`.
   - `r_norm = ((r - 1) % Period) + 1`.
   - Handle cases where the range spans multiple periods.
     - If `r - l >= Period`, the answer is simply the total distinct letters in the full period (which is `a + 1`).
     - If the range wraps around the period end (e.g., l_norm > r_norm), we split into two segments: `[l_norm, Period]` and `[1, r_norm]`.

3. **Distinct Counting:**
   - Iterate through the required indices (max `Period` iterations, i.e., 48).
   - Maintain a bitmask (13 bits) or a valid flag array (size 13) to track seen letters.
   - Accumulate the count.

4. **Timing:**
   - Start the sequence generation (combinational or FSM).
   - Once sequence is ready (or defined), process the query range.
   - Assert `done`.

**Detailed Instructions:**
- Use an FSM for control.
- States: IDLE, GENERATE_SEQ, CALCULATE, DONE.
- `GENERATE_SEQ`: Fill a `seq_storage` array (size 48) with letter IDs. Use combinational logic or a counter.
- `CALCULATE`: Compute `l_norm`, `r_norm`. Determine if full period coverage exists. If not, iterate through the relevant range of `seq_storage` to count distinct elements.
- `seq_storage`: Declare as `reg [3:0] seq_storage [0:47];` (4-bit letter ID).
- Constraints: `l` and `r` are 32-bit, so use 32-bit arithmetic for modulo operations.
- Optimization: Since `Period` is small, the calculation is fast. Just ensure robust handling of the wrap-around logic.
