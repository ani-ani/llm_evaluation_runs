Design a combinational Verilog module named 'voting_optimizer' that computes the minimum number of swaps needed to ensure party 1 wins in a simplified voting system.

The module handles a small fixed-size scenario with up to 8 citizens (n <= 8). The input string is represented as a fixed-size array of 8 elements, where each element is 3 bits:
- 001 (1): Party 1 voter
- 010 (2): Party 2 voter
- 100 (0): Teller

The module computes the minimum number of adjacent swaps of tellers (swapping a teller with an adjacent voter) required to rearrange the sequence such that party 1 wins. A teller awards a point to the party with more votes at that moment. Party 1 wins if it has strictly more points than Party 2 at the end.

Inputs:
input [7:0][2:0] citizens // Array of 8 citizens, each 3 bits (1=001, 2=010, 0=100)
input [2:0] n // Valid number of citizens (1 to 8)

Outputs:
output [3:0] min_swaps // Minimum swaps needed (0-15). If impossible (or requires >15 swaps), output 15.
output win_possible // 1 if win is possible within constraints, 0 otherwise

The module should:
1. Analyze the initial configuration
2. Determine all possible positions for tellers (tellers can move, voters are fixed relative to each other)
3. For each valid configuration, simulate the voting process
4. Track the minimum swaps required for configurations where Party 1 wins
5. Output the minimum swaps and whether a win is possible

Implementation approach:
- The citizens array contains fixed types. Voters maintain relative order, only tellers move.
- Swaps are adjacent swaps of a teller and a voter.
- The cost is the sum of distances each teller moves from its original position.
- For small n, use exhaustive search over valid permutations of teller positions.
- Output min_swaps (capped at 15) and win_possible flag.
