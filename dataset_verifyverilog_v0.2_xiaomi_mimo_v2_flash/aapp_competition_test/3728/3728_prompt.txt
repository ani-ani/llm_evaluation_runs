Design a sequential Verilog module named 'table_sorter' that checks if a table of permutations can be sorted by swapping two columns (at most once) and optionally one swap per row.

The module handles a table of size 4 rows and 8 columns (scaled down from the problem's max 20x20).

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [2:0] row_idx // Current row index (0-3) for streaming input
input [7:0] col_val_0, col_val_1, col_val_2, col_val_3, col_val_4, col_val_5, col_val_6, col_val_7 // Values for current row (1-8)

Outputs:
output reg result // High if the table can be sorted (YES)
output reg done // High when computation complete

Behavior:
1. The module receives the table row-by-row (streaming input via row_idx and col_val_X ports).
2. It must store the table internally (4 rows x 8 columns).
3. Upon 'start' being high, it iterates through all pairs of columns (c1, c2) where c1 <= c2 (includes c1=c2 for identity).
4. For each column pair, it conceptually swaps those two columns across all rows.
5. It then checks if every row in the modified table is 'sortable'. A row is sortable if, after the column swap, it differs from the identity [1,2,3,4,5,6,7,8] by at most 2 elements (meaning 0 or 1 swap within the row is needed).
6. If any column pair results in all rows being sortable, set result=1 and done=1.
7. If no such pair exists, set result=0 and done=1.

Latency: The process is computationally intensive. Allow up to 1024 clock cycles after start to complete the search.
Use a state machine: IDLE, LOAD, PROCESS, DONE.

Note: Values are standard integers 1-8. No fixed-point arithmetic needed.
