Design a sequential Verilog module named 'dial_game' that simulates Luka's analog dial game with scaled parameters.

The module manages 8 dials (N=8), each with values 0-9 (4 bits). It processes up to 8 operations (M=8). The module operates in cycles: on each cycle where 'start' is asserted, it reads a range [A, B], calculates the sum of dials in that range, outputs the sum, and then increments those dials (cyclic 0->9).

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // High to process the next operation
input [3:0] A // Start index of range (1-based, 1-8)
input [3:0] B // End index of range (1-based, 1-8)

Outputs:
output reg [7:0] sum_out // The calculated sum for the current operation (max sum 8*9=72 fits in 8 bits)
output reg done // High for one cycle when operation is complete

Internal Logic:
- Dials: Use 8 registers of 4 bits each to store dial values (initially loaded from an external source or testbench, but for module spec, assume they are initialized to 0 or managed internally). Let's make the module stateful, handling the increment logic internally.
- State Machine: IDLE, CALCULATE_SUM, UPDATE_VALUES, DONE.
- In IDLE: wait for start.
- In CALCULATE_SUM: iterate from A to B, accumulate values. This takes several cycles (max 8 cycles).
- In UPDATE_VALUES: iterate from A to B, increment values (handle wrap-around 9->0). Takes several cycles.
- In DONE: assert done signal for 1 cycle.

Behavior:
1. When start is high, transition to CALCULATE_SUM.
2. Calculate sum: sum = sum + dial[i] for i in [A, B].
3. Output sum.
4. Transition to UPDATE_VALUES.
5. Update dials: dial[i] = (dial[i] + 1) % 10 for i in [A, B].
6. Transition to DONE, assert done.
7. Return to IDLE.

Constraints:
- N=8, M=8 (implied by internal state or testbench usage).
- Sum fits in 8 bits (8*9=72).
- Indices A, B are 1-based. Convert to 0-based internally (index = A-1).
