Design a sequential Verilog module named 'chair_arrangement' that computes the minimum number of chairs required for seating guests.

Problem Description:
You have n guests, each needing at least l_i free chairs to the left and r_i free chairs to the right in a circle. The optimal arrangement is to sort the l and r arrays separately and sum max(l_i, r_i) for each guest, plus n (one chair per guest).

Constraints:
- n <= 16 guests (scaled down from 10^5)
- l_i, r_i <= 1000 (scaled down from 10^9 to fit 32-bit arithmetic)
- Use 32-bit unsigned arithmetic for all calculations

Module Interface:
module chair_arrangement (
    input clk,                // Clock signal
    input rst_n,              // Active-low reset
    input start,              // Start computation
    input [31:0] l_i,         // Current guest's left requirement
    input [31:0] r_i,         // Current guest's right requirement
    input [4:0] guest_index,  // Index of current guest (0 to 15)
    input [4:0] n,            // Total number of guests
    output reg [39:0] result, // Result (max 16 * (1000 + 1000) + 16 ~ 32016)
    output reg done           // High when computation complete
);

Behavioral Description:
The module should implement the greedy algorithm:
1. Receive l_i and r_i values for n guests sequentially (cycle by cycle)
2. Store l and r values in internal arrays
3. On 'start', sort both arrays using a simple bubble sort or selection sort
4. Calculate sum = sum(max(l_i, r_i)) + n
5. Output result and set done high

Timing:
- Input phase: n cycles to receive all guests
- Processing phase: ~n^2 cycles for sorting (simplified)
- Output phase: 1 cycle
- Total latency: ~260 cycles max for n=16

Use state machine states: IDLE, INPUT_LOAD, SORT_L, SORT_R, CALCULATE, DONE.

Note: Since this is for benchmarking, implement a simplified sorting mechanism that works for small n. The exact cycle count is less critical than correct logic.
