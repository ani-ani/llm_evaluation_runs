Design a sequential Verilog module named 'coprime_counter' that counts the number of ordered pairs of co-prime integers (x, y) within given ranges [a, b] and [c, d].

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [7:0] a // Lower bound of first range (1 to 8)
input [7:0] b // Upper bound of first range (1 to 8)
input [7:0] c // Lower bound of second range (1 to 8)
input [7:0] d // Upper bound of second range (1 to 8)

Outputs:
output reg [7:0] result // Number of coprime pairs (max 64 for ranges 1-8)
output reg done // High when computation complete

Specification:
The module should implement an iterative solution to count coprime pairs.
Use a state machine with states: IDLE, CALC_GCD, CHECK_GCD, NEXT_PAIR, DONE.

1. IDLE: Wait for start signal. When start goes high, initialize x = a, y = c, result = 0. Transition to CALC_GCD.
2. CALC_GCD: Compute GCD of current x and y using a simple iterative algorithm (Euclidean algorithm) in a sub-state machine or combinational block. Since inputs are small (max 8), this can complete in a few cycles.
3. CHECK_GCD: Check if GCD == 1. If true, increment result.
4. NEXT_PAIR: Update y. If y < d, increment y and go back to CALC_GCD. If y == d, set y = c and check x. If x < b, increment x and go back to CALC_GCD. If x == b, transition to DONE.
5. DONE: Assert done signal.

The GCD computation logic should be internal to the module. Since inputs are small, we can use a simple loop: while (b != 0) { temp = b; b = a % b; a = temp; }.

Note: Inputs a, b, c, d are 8-bit integers. Assume ranges are small (e.g., 1-8) to keep state count manageable. Result fits in 8 bits.

Latency: Approximately (b-a+1)*(d-c+1) * GCD_Cycles + Overhead.
