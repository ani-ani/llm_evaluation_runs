Design a sequential Verilog module named 'graph_orientability' that determines if an undirected graph can be oriented to remain strongly connected.

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [3:0] n_nodes // Number of nodes (1-4)
input [3:0] n_edges // Number of edges (1-6)
input [2:0] edge_u [0:5] // Source node for each edge (1-indexed)
input [2:0] edge_v [0:5] // Destination node for each edge (1-indexed)

Outputs:
output reg possible // High if orientation possible
output reg [2:0] out_u [0:5] // Oriented source for each edge
output reg [2:0] out_v [0:5] // Oriented destination for each edge
output reg valid // High when outputs are valid
output reg done // High when computation complete

Specification:
The module should determine if the graph can be oriented such that it remains strongly connected.
A graph CAN be oriented to remain strongly connected if and only if it contains NO bridges (cut-edges).
If no bridges exist, any orientation works (we output the original edges).

Algorithm:
1. Build adjacency matrix from edge list (4x4 for max 4 nodes)
2. For each edge, temporarily remove it and check connectivity using DFS/BFS
3. If any edge removal disconnects the graph, that edge is a bridge
4. If any bridge exists, impossible (output possible=0)
5. If no bridges, possible (output possible=1, and original edges as orientation)

State Machine States:
- IDLE: Wait for start signal
- BUILD: Construct adjacency matrix
- CHECK_EDGE: For current edge, remove it temporarily
- CONNECTIVITY: Run DFS from node 1 to check if all nodes reachable
- ANALYZE: Check if all nodes were reached
- COMPLETE: Set outputs and done signal

Latency: Approximately 50-100 clock cycles depending on graph size.
Use 8-bit counters for DFS stack and visited tracking.

Edge Case: For N=1, always possible (trivial). For N=2 with M=1, it's a bridge (impossible).
For cycles (N=3 with 3 edges forming triangle), no bridges (possible).
