Design a sequential Verilog module named 'gem_collector' that implements a simplified gem collection algorithm.

Problem Adaptation:
- Maximum 8 gems (n <= 8)
- Track width w <= 64
- Finish height h <= 256
- Ratio r is fixed to 1 (horizontal speed = vertical speed)
- Gems coordinates are 8-bit values
- Start position can be any x in [0, w]

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [2:0] n // number of gems (1 to 8)
input [5:0] w // track width (0 to 63)
input [7:0] h // finish height (0 to 255)
input [2:0] gem_index // index for gem input (0 to n-1)
input [5:0] gem_x // x coordinate of current gem
input [7:0] gem_y // y coordinate of current gem
input gem_wr // write enable for gem input

Outputs:
output reg [2:0] max_gems // maximum number of gems that can be collected
output reg done // high when computation complete

Behavior:
The module must:
1. Accept gem coordinates into internal storage when gem_wr is asserted
2. When start is asserted, sort gems by y-coordinate (ascending)
3. Use dynamic programming to find max gems collectible
4. For each gem, determine if it's reachable from previous gems or start line
5. A gem at (x_i, y_i) is reachable from (x_j, y_j) if |x_i - x_j| <= (y_i - y_j) * r
6. Track max count for each reachable gem
7. Result is max count over all gems
8. Latency: Done within 512 clock cycles after start

Use state machine with states: IDLE, LOAD_GEMS, SORT_GEMS, DP_PROCESS, DONE.
For sorting, use bubble sort since n is small.
For DP, iterate through sorted gems and check reachability from all previous gems.
Output max_gems should be the maximum collectible gems.

All arithmetic must be performed using 8-bit unsigned integers (scaled down from original problem constraints).
