Design a sequential Verilog module named 'martian_tax_solver' that solves the Martian tax problem.

Problem: Given n banknote denominations and a base k, determine which digits d (0 <= d < k) can appear as the last digit of the sum of any number of banknotes.

Mathematical Insight: A remainder d is achievable if and only if d is a multiple of G = gcd(a_1, a_2, ..., a_n, k).

Module Specification:
The module should first compute g = gcd(a_i, k) for all i, then compute G = gcd(g, k). Finally, it should determine all d such that d = (m * G) mod k for integer m.

Since n can be large but k is small (scaled to <=30), we can iterate through the banknotes.

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [2:0] n // Number of denominations (max 5 in test cases, scaled)
input [4:0] k // Base of number system (max 30, fits in 5 bits)
input [29:0] a // Packed array of banknote denominations (5 denominations * 6 bits each, assuming scaled values)

Outputs:
output reg [4:0] result_d // The current valid digit d being output
output reg [2:0] result_index // Index of the current result
output reg valid // High when result_d is valid
output reg done // High when computation is complete

Internal Logic:
1. IDLE: Wait for start signal.
2. GCD_CALC: Iteratively compute gcd of all denominations and k.
   - Use a state machine to fetch each 'a' and update 'g'.
3. RESULT_GEN: Generate multiples of the final gcd modulo k.
   - Store results in a small buffer or output sequentially.

Latency: Approximately (n + k) clock cycles.

Data Representation: Inputs 'a' are integers. Output 'd' is an integer.
