Design a sequential Verilog module named 'council_solver' that finds a valid assignment of residents to clubs satisfying the party balance constraint.

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start solving

// Configuration (Fixed for this scaled version: Max 8 Residents, 4 Clubs, 4 Parties)
// Data valid during LOAD state
input [3:0] num_residents // Actual number of residents (1-8)
input [3:0] num_clubs // Actual number of clubs (1-4)

// Resident Data (concatenated into wide vector or loaded sequentially)
// For simplicity, we load one resident per clock cycle using 'resident_data' and 'resident_valid'
input [7:0] resident_id // ASCII ID (simplified to 1 byte)
input [7:0] party_id // ASCII ID for party
input [3:0] club_mask // Bitmask of clubs this resident belongs to (up to 4 clubs)
input load_valid // High when loading resident data

Outputs:
output reg solved // High when solution found
output reg impossible // High when no solution exists
output reg [7:0] result_club_id // Club ID of the assignment (ASCII)
output reg [7:0] result_resident_id // Resident ID of the assignment (ASCII)
output reg result_valid // High when result data is valid

Constraints:
- Use a state machine to manage Loading, Solving, and Output states.
- The solver should check all valid combinations of residents to clubs.
- It must enforce that no resident represents more than one club.
- It must enforce that for every party, the number of council members from that party is strictly less than half the total council size (i.e., count < ceil(num_clubs/2)).
- If a solution is found, assert 'solved' and output assignments sequentially (one per clock cycle).
- If no solution exists after checking all possibilities, assert 'impossible'.
- Latency: Depends on search space, but allow up to 2^16 cycles for the search.

Scaling: 
- Max Residents: 8
- Max Clubs: 4
- Max Parties: 4
- IDs are treated as 8-bit values (ASCII characters).
