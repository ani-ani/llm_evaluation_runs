Design a sequential Verilog module named 'theorem_proof_minimizer' that computes the minimum total length needed to prove Theorem 0.

The module implements the following algorithm:
- For each theorem, find the minimum cost proof considering dependencies
- Use memoization to avoid recomputation
- Return the total cost for Theorem 0

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [4:0] num_theorems // number of theorems (1-20)
input [5:0] proof_count [0:19] // number of proofs for each theorem (1-10)
input [31:0] proof_length [0:199] // length of each proof (up to 200 proofs total)
input [4:0] proof_dep_count [0:199] // number of dependencies for each proof
input [4:0] proof_deps [0:199][0:19] // dependencies for each proof (20 slots per proof, unused entries = 31)

Outputs:
output reg [31:0] min_length // minimum total length for Theorem 0
output reg done // high when computation complete

Specify latency: Result valid 1000 clock cycles after start asserted (worst case for 20 theorems with dependencies).
Use state machine with states: IDLE, LOAD_DATA, COMPUTE_COSTS, CHECK_DONE, OUTPUT_RESULT, DONE.

Implementation details:
- Store proof data in internal arrays
- Use DP array cost[0:19] for minimum cost of each theorem
- Initialize cost array to 0xFFFFFFFF (infinity)
- For each theorem, compute min over all its proofs: proof_length + sum of dependency costs
- Handle cycles by detecting when cost computation references current theorem
- Return cost[0] as result

Use 32-bit arithmetic throughout. All inputs are provided in parallel but may represent a sequential loading process.
