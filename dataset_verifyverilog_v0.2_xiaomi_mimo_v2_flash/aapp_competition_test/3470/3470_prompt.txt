Design a combinational Verilog module named 'minesweeper_safe' that identifies safe cells in a Minesweeper pattern.

Problem Analysis:
- There are 4n+4 red cells surrounding an n×n square of 1s
- Each blue 1 cell is adjacent to exactly 1 mine
- Red cells are indexed clockwise from 1 to 4n+4 starting at bottom-left
- For n=3, indices are: bottom=1-3, right=4-6, top=7-9, left=10-12

Pattern Analysis for n=3:
- Corner red cells (1, 3, 7, 9, 13, 15) are adjacent to only 2 blue 1s each
- Edge red cells (2, 4, 6, 8, 10, 12, 14, 16) are adjacent to 3 blue 1s each
- Each corner blue 1 (4 corners) is adjacent to 2 red cells
- Each edge blue 1 (4(n-1) = 8 for n=3) is adjacent to 3 red cells

Logical deduction:
For n=3, 12 blue 1 cells need exactly 1 mine each, but only 16 red cells exist.
Key insight: Corner red cells (odd indices) are only adjacent to 2 blue 1s, while edge red cells (even indices) are adjacent to 3.

Safe cells are:
- All even-indexed cells (2, 4, 6, 8, 10, 12, 14, 16) - they touch 3 blues, and corners only touch 2 reds
- The pattern: cells 2, 4, 6, 8, 10, 12, 14, 16 are always safe

Module Specifications:
Inputs:
input [2:0] n // n value (1-3, mapped to 1, 2, 3)

Outputs:
output [3:0] count // number of safe cells (0 to 16)
output [15:0] safe_mask // bit mask where bit i=1 means cell i+1 is safe

Behavior:
For n=1: 8 cells, all are corners, output count=0, mask=0
For n=2: 12 cells, analyze pattern
For n=3: 16 cells, even indices are safe, output count=8, mask=0xAAAA (1010101010101010)

The module should compute this purely combinationally.
