Design a Verilog module that determines if a trick shot in a billiards simulation is feasible. The module takes 8-bit integer inputs for table dimensions (width `w`, length `l`), ball radius `r`, and position of three balls (1, 2, 3) given as 8-bit x, y coordinates. The shot line starts at a height `h` (8-bit) from the bottom. The goal is to find a distance `d` (from left edge) and angle `theta` (in degrees) such that:
1. Cue ball at (d, h) hits ball 1.
2. Cue ball ricochets to hit ball 2, which falls into the top-left hole (0, l).
3. Ball 1, after being hit, hits ball 3, which falls into the top-right hole (w, l).

Physics Model:
- Cue ball moves along vector V_cue.
- Collision: Ball A (stationary) starts moving in vector N (from center of B to center of A). Ball B (moving) reflects V across N.
- Sinking: Ball center must pass exactly over the hole coordinates.

Scale & Precision:
- Use fixed-point arithmetic (Q16.16) for calculations.
- Search `d` over the range [r, w-r] and `theta` over [0, 180] degrees with a step size of 0.5 degrees (represent as integers 0 to 360).
- Output the first valid `(d, theta)` pair found, rounded to nearest hundredth.
- If no solution found after scanning all parameters, output "impossible".

Interface:
- Inputs: `clk`, `rst_n` (active low), `start` (pulse).
- Constants: `w`, `l`, `r`, `h`, `x1`, `y1`, `x2`, `y2`, `x3`, `y3` (all 8-bit registers).
- Outputs: `result_valid` (1 bit), `d_out` (16-bit integer representing d*100), `theta_out` (16-bit integer representing theta*100), `impossible` (1 bit).
- Timing: Operate as a state machine. Accept `start` pulse, compute, assert `result_valid` when done (within ~10,000 cycles). On reset, clear outputs.

Implementation Details:
- Implement fixed-point multiply and square root helpers (non-restoring method).
- State Machine: IDLE -> CALCULATE -> CHECK -> OUTPUT.
- In CALCULATE, iterate `theta_i` from 0 to 360 (representing 0.0 to 180.0 degrees) and `d_i` from `r` to `w-r`.
- For each pair, calculate intersection points using vector geometry.
- Verify constraints: 
  1. Cue->Ball1 intersection exists.
  2. Reflected vector from Ball1->Ball2 intersects hole 1.
  3. Vector from Ball1->Ball3 intersects hole 2.
  4. No intermediate collisions (check generic exclusion).
- Output format: `d_out` and `theta_out` should be integers where value / 100.0 is the result.
