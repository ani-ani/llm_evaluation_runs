Implement a module that simulates the slime merging game using a binary counter approach. The input n represents the number of slimes added sequentially (each starting as value 1). The final state corresponds to the binary representation of n, where a bit set at position i (0-indexed) means a slime of value i+1 is present.

**Interface Specification:**

Inputs:
  clk: System clock, rising edge triggered
  rst_n: Active-low synchronous reset
  start: 1-cycle pulse to begin computation
  n_in: 17-bit unsigned integer (0 to 100,000)

Outputs:
  result_v: 5-bit array of size 17 (values 1-17)
  result_len: 5-bit integer (0 to 17)
  done: 1-cycle pulse indicating result is valid

**Timing Requirements:**
- Start pulse initiates computation
- Computation must complete within 200 cycles
- result_v and result_len are valid when done=1
- Reset clears done=0 and result_len=0

**Algorithm Logic:**
1. On start, load n_in into a counter
2. Initialize output array index counter (bit position)
3. While counter > 0:
   - If LSB is 1: record slime value = bit_position + 1
   - Right-shift counter by 1
   - Increment bit_position
4. Output the recorded values in reverse order (MSB to LSB)

**Implementation Notes:**
- Use a FSM with states: IDLE, PROCESSING, OUTPUT, DONE
- Maximum 17 iterations for n=100,000
- Store values in a fixed-size register array
- Result order is important: highest value first
- When n=0, output is empty (result_len=0)
