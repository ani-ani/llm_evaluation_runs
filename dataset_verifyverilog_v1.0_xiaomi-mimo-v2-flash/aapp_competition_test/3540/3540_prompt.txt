Implement a Verilog module that computes the minimum number of moves to solve a 4x4 toroidal sliding puzzle.

Module Interface:
- Inputs:
  - clk: clock
  - rst_n: active-low synchronous reset
  - start: 1-cycle pulse to start computation
  - grid [15:0][1:0]: 16 cells, each 2 bits encoding color (00=R, 01=G, 10=B, 11=Y)
- Outputs:
  - moves [3:0]: minimum moves (0-12)
  - done: 1-cycle pulse indicating result is valid

Implementation Details:
1. Represent the 16x2-bit grid as a 32-bit integer (flattened row-major).
2. Define valid moves:
   - Row shift left/right (4 rows, each can shift cyclically by 1).
   - Column shift up/down (4 columns, each can shift cyclically by 1).
   Total 16 possible moves.
3. The state space is 4^16 (4.29 billion), too large for direct memory. However, the problem guarantees solution in <13 moves. Use a precomputed lookup table (ROM) generated by an external Python script. The ROM will map 32-bit input state to 4-bit distance.
   - Alternatively, implement a BFS engine with a 65k-entry visited RAM (16-bit state hashed to 16-bit address). Since 4^16 > 65k, use a Bloom filter or simple depth-limited iterative deepening (max depth 12). Given the constraints, a ROM is simpler for synthesis.
4. For the ROM approach: Use a Python script to generate a .memh file containing all reachable states (up to depth 12). The ROM will be 32-bit address, 4-bit data.
5. Module operation:
   - On start, register the input 32-bit state.
   - Read the ROM asynchronously (or synchronously with 1-cycle latency).
   - Output the distance (0-12). If not found (should not happen), output 15.
   - Assert done for 1 cycle.
