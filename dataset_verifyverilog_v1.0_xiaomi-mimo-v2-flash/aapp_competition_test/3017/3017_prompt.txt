Design a Verilog module that counts numbers ≤ n (up to 19 digits) containing a specific substring (up to 19 digits). 

### Interface Specs:
- **Inputs**:
  - `clk`, `rst_n`: Standard synchronous clock/reset (active low).
  - `start`: 1-cycle pulse to begin computation.
  - `n_digits[19][4]`: Input number N stored as 19 packed 4-bit decimal digits (0-9), padded with leading zeros. Index 0 is MSB.
  - `n_len[5]`: Actual length of N (1 to 19).
  - `pattern_digits[19][4]`: The substring (2^e) stored as packed 4-bit digits. Index 0 is MSB.
  - `p_len[5]`: Actual length of pattern (1 to 19).

- **Outputs**:
  - `result[63]`: 64-bit result count.
  - `done`: 1-cycle pulse indicating valid result.

### Implementation Requirements:
1. **Preprocessing (KMP Failure Function)**: Calculate the prefix function (lps array) for the pattern once `start` is asserted. This requires a loop over `p_len`.
2. **Digit DP State Machine**: Use a deterministic finite automaton (DFA) structure. The state must include:
   - `pos`: Current digit position (0 to 19).
   - `tight`: Boolean flag (0 or 1) indicating if the prefix matches N exactly.
   - `started`: Boolean flag indicating if we have started the number (to handle leading zeros).
   - `match_len`: Current length of matching suffix (KMP state), 0 to `p_len`.
   - `found`: Boolean flag indicating if the pattern has been fully matched at any point.
3. **Memory**: Use internal BRAM or distributed RAM arrays to store DP states. Since the state space is large (20 * 2 * 2 * 20 * 2 ≈ 3200 states), you should iterate through positions. 
   - **Simplification**: Instead of storing all states, use a recursive-like iterative approach with a stack or just process position by position, keeping track of counts for all `(tight, started, match_len, found)` combinations for the current position.
4. **Data Types**:
   - Pattern digits: `reg [3:0] pattern [0:18];`
   - DP Counts: `reg [63:0] dp_tight_started_found [20][2][2][2];` (Size: 20 * 2 * 2 * 2 * 8 bytes = 1280 bytes). Alternatively, use two buffers `dp_cur` and `dp_next` to save memory.
   - LPS array: `reg [4:0] lps [0:18];` (5 bits for index up to 19).

### Logic Flow:
1. **IDLE**: Wait for `start`. On start, compute LPS array for the pattern. Then initialize DP state.
2. **DP LOOP**:
   - Iterate `pos` from 0 to `n_len - 1`.
   - For each `pos`, iterate through all valid previous states (tight, started, match_len, found).
   - Determine the range of digits allowed at this position (0-9 if `tight=0`, 0-`n_digits[pos]` if `tight=1`).
   - For each allowed digit, calculate:
     - New `tight`: `tight & (digit == n_digits[pos])`.
     - New `started`: `started | (digit != 0)`.
     - New `match_len`: Update using KMP transition logic (check `pattern[match_len]` vs `digit`, fallback to `lps` if mismatch).
     - New `found`: `found | (new_match_len == p_len)`.
   - Accumulate counts into `dp_next`.
   - Swap buffers.
3. **AGGREGATION**: After processing all positions, sum up counts where `found` is true.
4. **DONE**: Assert `done` for 1 cycle.

### Constraints:
- Clock frequency: Assume >100 MHz.
- Max cycles: < 10,000 cycles (for 19 digits * 10 max digits * overhead).
- Use non-blocking assignments for state transitions.
- Ensure no combinational loops.
