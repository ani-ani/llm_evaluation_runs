Design a Verilog module for a dynamic programming solution to count task assignment ways.

**Problem Overview**:
- N tasks (difficulties 1..N)
- Two task types per difficulty:
  - Type A: Exact difficulty i (count A[i])
  - Type B: Difficulty i or i+1 (count B[i], for i=1..N-1)
- Goal: Count assignments where each difficulty 1..N gets exactly one task
- Result modulo 1000000007

**Algorithm**:
Process difficulties 1 to N sequentially. At each difficulty i:
- State: boolean `prev_selected` (was task from B[i-1] used for difficulty i-1?)
- Transitions:
  1. If `prev_selected` is false: Can use A[i] or B[i]
  2. If `prev_selected` is true: Must use A[i] (B[i] already used for i)
- DP recurrence:
  dp[i][0] = (dp[i-1][0] * (A[i] + B[i])) + (dp[i-1][1] * A[i])
  dp[i][1] = dp[i-1][0] * B[i]
- Base: dp[0][0] = 1, dp[0][1] = 0
- Answer: dp[N][0]

**Module Interface**:
- Inputs:
  - `clk`: System clock (rising edge)
  - `rst_n`: Active-low synchronous reset
  - `start`: 1-cycle start pulse
  - `N`: 5-bit input (max 32 tasks)
  - `A_addr`: 5-bit address for array A (difficulty index)
  - `A_data`: 32-bit value for A[i]
  - `B_addr`: 5-bit address for array B (index i, 0..N-2)
  - `B_data`: 32-bit value for B[i]
- Outputs:
  - `result`: 32-bit final count modulo 1000000007
  - `done`: 1-cycle pulse when computation completes
  - `busy`: High while computing

**Behavior**:
- On `start`: Reset internal state, begin processing from i=1
- Reading inputs: For each difficulty i, need to fetch A[i] and B[i]
- Use a counter to iterate i from 1 to N
- Internal state: `dp_prev_0`, `dp_prev_1` (32-bit registers)
- Computation per cycle: Fetch A[i], B[i], compute new dp values, update state
- After N cycles: Output dp[N][0] on `result`, pulse `done`
- Modulo operation: (x * y) mod M computed via `((x mod M) * (y mod M)) mod M`

**Constraints**:
- N ≤ 32 (5-bit)
- Values up to 10^9 (fits in 32-bit)
- Modulo = 1000000007 (30-bit)
- Multiplication: Use 64-bit intermediate to avoid overflow
- Timing: Done within 2*N + 10 cycles

**Implementation Notes**:
- The module should have a state machine with states: IDLE, FETCH, COMPUTE, DONE
- For fetching A/B values, assume A and B arrays are provided via sequential reads
  (i.e., external logic presents A[i] and B[i] when requested)
- Alternatively, embed a small RAM (32x32-bit) for A and B, filled via write ports
  during a setup phase before `start`
- Use 32-bit counters for DP values
- Use 64-bit (or 33-bit) for multiplication result before modulo
- The reset sets dp_prev_0=1, dp_prev_1=0, counter=0

**Testbench Requirements**:
- Must simulate with N up to 10
- Must verify against sample inputs
- Use helper functions for array access and modulo arithmetic
- Check `done` signal and `result` value
- Handle modulo in testbench as well

**Verilog Module Specification**:
- Module name: `task_counter`
- Parameters: `MOD = 1000000007` (30-bit), `MAX_N = 32`
- Inputs: `clk, rst_n, start, N[4:0], A_addr[4:0], A_data[31:0], B_addr[4:0], B_data[31:0]`
- Outputs: `result[31:0], done, busy`
- Internal: State machine, registers for dp_0, dp_1, counter_i, temp_64
- Timing: Start -> busy high -> after N cycles -> done pulse with result

**Edge Cases**:
- N=2: Minimum case
- A[i] or B[i] can be 0
- For i=N, B[N] doesn't exist; B_data should be 0
- Modulo arithmetic after each multiplication/addition
