Verilog HDL Module Specification: Beautiful Rectangle Generator

=== PROBLEM CONTEXT ===
Given n integers (n ≤ 4000), create the largest beautiful rectangle (matrix) where each row and column has distinct values. Scaled from n=400k to n=4000 for hardware feasibility.

=== INTERFACE ===
Inputs:
  clk: System clock, rising edge active
  rst_n: Active-low synchronous reset
  start: 1-cycle pulse to begin operation
  len_in: 4-bit input (actual n, max 4000, but we'll process in chunks)
  data_in: 32-bit integer input (one per clock cycle, streaming)
  data_valid: Input data valid flag
  data_last: Input last data flag

Outputs:
  result_area: 16-bit maximum area value
  result_h: 8-bit rectangle height (rows)
  result_w: 8-bit rectangle width (cols)
  done: 1-cycle pulse when entire operation completes
  out_data: 32-bit output value for grid
  out_valid: 1-cycle pulse when outputting grid cell
  out_x: 8-bit column index (0-based)
  out_y: 8-bit row index (0-based)

=== INTERNAL ARCHITECTURE ===
1. Count Frequency (FSM):
   - Use 16-bit counters for values (scaled 0..4095)
   - Store counts in RAM (4096 x 16-bit)
   - Process streaming input over multiple cycles
   - Output: count histogram

2. Sort Counts (Sorting Network):
   - Sort frequencies from highest to lowest
   - Use 16-element sorting network (bitonic sort)
   - Input: 16 frequencies + 16 value IDs
   - Output: sorted frequency-value pairs

3. Find Optimal Rectangle (Optimization Loop):
   - Try heights h from 1 to min(64, sqrt(n))
   - For each h, calculate width w = floor(available_numbers / h)
   - Use prefix sums to count numbers with freq ≥ h
   - Find max area where w ≥ h
   - Output: optimal (h, w, area)

4. Fill Grid (Construction Phase):
   - Use diagonal filling algorithm
   - For each column in width:
     - For each row in height:
       - Place next number from sorted list
       - Track usage count per number
       - Wrap to next number when count reached h
   - Use (row + col) mod w for column rotation
   - Store grid in 64x64 BRAM
   - Stream output in row-major order

=== SCALING & CONSTRAINTS ===
- Max input n: 4000 (scaled from 400k)
- Max values: 2^32-1 (32-bit integers)
- Frequency counting: 16-bit counters (max count 4000)
- Grid dimensions: 64x64 max (4096 cells)
- Sorting: 16 elements maximum (top frequency values)
- Timing: Complete within 10,000 clock cycles
- Memory: 64x64 grid array (32-bit values)

=== FSM STATES ===
0: IDLE
1: READ_INPUT (streaming data)
2: SORT_COUNTS (sorting network)
3: FIND_RECT (optimize h,w)
4: FILL_GRID (construct matrix)
5: OUTPUT (stream grid)
6: DONE

=== ALGORITHM DETAILS ===
1. Counting: Maintain histogram in block RAM
2. Sorting: Use 16-stage bitonic network (2^4 stages)
3. Optimization: For h from 1..64:
   - total = sum(min(count, h) for all values)
   - w = total / h
   - if w >= h: candidate area = h*w
4. Grid Filling:
   - Use diagonal placement: grid[(r+c)%w][r] = value
   - Track per-value usage (0..h)
   - Move to next value when count == h
