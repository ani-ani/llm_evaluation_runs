You are to design a Verilog module that computes the minimum number of operations to arrange numbered cards in a pile. 

## Problem Analysis & Constraints
- Input: n (1..16), hand cards `a[0:15]`, pile cards `b[0:15]`. Cards are 0 (empty) or 1..16.
- Logic: 
  1. Check if pile is already sorted [1..n]. Output 0.
  2. Check if pile contains a suffix starting with '1' that is consecutive (1,2,3...). If the remaining cards in hand can cover the missing numbers in order (e.g., if suffix is [1,2], check if 3,4... are in hand or can be drawn), then the answer is `n - length(suffix)`.
  3. Otherwise, the answer is `n + max(b[i] - i + 1)` for all i where b[i] != 0.

## Interface Specification
Inputs:
  clk: System clock (rising edge)
  rst_n: Active-low synchronous reset
  start: Start processing (1-cycle pulse)
  n: 4-bit unsigned integer (1-16)
  a[0:15]: 16x4-bit array (hand cards, 0=empty)
  b[0:15]: 16x4-bit array (pile cards, 0=empty)

Outputs:
  result: 16-bit unsigned integer (minimum operations)
  done: 1-cycle pulse indicating valid result

## Timing & Behavior
- Idle state: `done=0`, `result=0`.
- When `start=1`: Latch inputs and begin computation.
- Processing: Must complete within 256 clock cycles.
- Result: Valid when `done=1`.

## Implementation Guidance
1. Use a finite state machine (FSM) with states: IDLE, CHECK_SORTED, CHECK_SUFFIX, CALC_MAX, FINISHED.
2. Use internal registers to store the inputs and intermediate values.
3. For `CHECK_SUFFIX`: 
   - Find index of card 1 in pile `b`. If found, verify if `b[idx..15]` is sequence `1,2,3...`.
   - If valid, check if missing numbers (after the suffix) are present in `a` or can be drawn. Specifically, for missing number `m`, check if `m` is in `a` OR if `m` appears in `b` before index `idx` (meaning it can be drawn).
   - If all missing numbers are available, answer is `n - length(suffix)`.
4. For `CALC_MAX`: Iterate `i` from 0 to 15. If `b[i] != 0` and `b[i] > i+1`, calculate `b[i] - (i+1)`. Find the maximum such value. The answer is `n + max_val`.
5. Ensure all arithmetic handles bit widths correctly (4-bit for values, 16-bit for result).
