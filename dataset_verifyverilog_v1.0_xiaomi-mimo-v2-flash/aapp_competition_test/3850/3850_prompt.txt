Design a Verilog module to find the minimum time for all people to reach the office with keys.

**Problem Scaling:**
- n (people) = 8 max
- k (keys) = 16 max
- Positions and office location are scaled to 16-bit unsigned integers (0-65535).
- Time/Distance is 16-bit unsigned.
- The algorithm uses a brute-force check of all valid key-to-person assignments (sliding window).

**Module Interface:**
- Inputs:
  - `clk`, `rst_n`: Standard synchronous control
  - `start`: 1-cycle pulse to initiate computation
  - `n`: 4-bit input (number of people, valid 1-8)
  - `k`: 5-bit input (number of keys, valid 1-16)
  - `p`: 16-bit input (office position)
  - `people[0:7]`: Array of 8x 16-bit inputs (person positions)
  - `keys[0:15]`: Array of 16x 16-bit inputs (key positions)
- Outputs:
  - `result`: 16-bit output (minimum time)
  - `done`: 1-cycle high when calculation is finished

**Implementation Logic:**
1. Sort the `people` and `keys` arrays internally using a simple sorting network (e.g., Bubble Sort) since they are small (max 16 elements). This must happen inside the module.
2. Iterate through all valid windows of keys of size `n` (from index 0 to `k-n`).
3. For each window, calculate the maximum time for the current assignment:
   - Time for person `i` assigned to key `window_index + i` = `abs(people[i] - key) + abs(key - p)`.
4. Keep track of the minimum of these maximum times.
5. Output the final minimum time.

**Timing:**
- Start asserted for 1 cycle.
- Computation may take up to 500 cycles (sorting + loop overhead).
- `done` goes high for 1 cycle when finished.

**Constraints:**
- Use unsigned arithmetic. Handle absolute differences manually or using comparator logic.
- Ensure internal indices are sized correctly (4-bit for n, 5-bit for k).
- Output `result` is valid only when `done` is high.
