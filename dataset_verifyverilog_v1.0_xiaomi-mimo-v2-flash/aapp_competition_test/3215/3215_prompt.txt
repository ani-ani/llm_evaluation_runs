Implement a Verilog module that calculates the minimum number of Riffle shuffles required to transform a sorted deck into a given permutation.

**Problem Analysis**: The minimum number of shuffles equals the number of bits in the binary representation of the permutation's cycle index. For a permutation `p`, this is `floor(log2(max(cycle_length)))` or the maximum bit position needed to represent any cycle length.

**Adaptation for Hardware**:
- Scale `n` to maximum 16 cards (testbench handles small n, hardware works for 16-bit widths)
- Use 16-bit fixed-width integers for all values
- The algorithm processes permutations to find the longest cycle in the permutation
- Output is the bit-length of that longest cycle length

**Module Interface**:
- Inputs:
  - `clk`: Clock signal (rising edge)
  - `rst_n`: Active-low synchronous reset
  - `start`: 1-cycle pulse to initiate computation
  - `card_in`: 16-bit input for each card value (sequential streaming)
  - `valid_in`: 1-bit valid signal for card_in
  - `len`: 4-bit input indicating number of cards (0-15)
- Outputs:
  - `result`: 4-bit output (max shuffles = floor(log2(16)) = 4)
  - `done`: 1-cycle pulse when computation complete
  - `idle`: High when ready for new input

**Implementation Requirements**:

Given the constraint n≤16, we can brute-force the reverse shuffle count:
- Start from given permutation
- Apply reverse shuffle operations
- Count steps until sorted
- Reverse shuffle: Given a deck, find all possible previous states (from interleaving two stacks)
- For n=16, maximum depth is small (≤16)
- Each reverse shuffle step checks all possible splits and interleavings (exponential but bounded by n)
