Implement a Verilog module that computes the maximum payment Sereja can pay given n and m weight values.

**Core Algorithm:**
1. Find the maximum number of distinct values 'k' (1-based) such that:
   - If k is odd: max_n(k) = k*(k-1)/2 + 1 <= n
   - If k is even: max_n(k) = k*k/2 <= n
2. Sort the m weight values in descending order.
3. Sum the top k weights (if k > m, sum all m weights).
4. Output the sum.

**Interface Specification:**
- Inputs:
  - `clk`: System clock (rising edge)
  - `rst_n`: Active-low synchronous reset
  - `start`: 1-cycle pulse to start processing
  - `n_i`: 32-bit input for n (max 2,000,000)
  - `m_i`: 32-bit input for m (max 100,000)
  - `w_i`: 32-bit input for weight values (serial stream)
  - `w_valid`: 1-bit valid flag for `w_i` (active high)
  - `w_done`: 1-bit flag indicating end of weight stream (1 cycle)
- Outputs:
  - `result`: 32-bit output (maximum payment)
  - `done`: 1-cycle pulse indicating result is valid

**Timing & Constraints:**
- Clock frequency: 100 MHz (10ns period)
- Reset: Assert `rst_n` low for 2 cycles, then high.
- After `start` goes high, set `n_i` and `m_i`. Wait for `clk` edge.
- Feed weights serially via `w_i`/`w_valid`. After all weights, pulse `w_done` high for 1 cycle.
- `done` will pulse high when calculation is complete (within 5000 cycles).
- Result is valid when `done` is high.
- Use 32-bit arithmetic for all calculations to avoid overflow.
- Implement a sorting buffer of size 100,000 (or a smaller fixed size like 512 for testability if needed, but handle full m logic).
- Implementation must be purely combinatorial/sequential logic, no dynamic memory allocation.
