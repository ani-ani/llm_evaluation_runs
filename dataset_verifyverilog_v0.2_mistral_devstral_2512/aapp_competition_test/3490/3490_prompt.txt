Design a sequential Verilog module named 'witch_collision' that determines if any of N witches' brooms will collide.

Problem Adaptation:
- N = 4 witches (fixed maximum)
- Broom length = 1m = 1.0 in fixed-point
- Coordinates and angles use Q16.16 fixed-point format
- Each broom has: pivot (x_i, y_i), angle r_i (radians)
- Broom tip position: (x_i + cos(r_i), y_i + sin(r_i))
- Check if line segments (pivot to tip) of any two witches intersect

Inputs:
input clk // clock signal
input rst_n // active-low reset  
input start // start computation
input [31:0] x0, y0, r0 // Witch 0: Q16.16 fixed-point
input [31:0] x1, y1, r1 // Witch 1: Q16.16 fixed-point
input [31:0] x2, y2, r2 // Witch 2: Q16.16 fixed-point
input [31:0] x3, y3, r3 // Witch 3: Q16.16 fixed-point

Outputs:
output reg crash // 1 if any collision detected
output reg done // high when computation complete

Specification:
- Use Q16.16 fixed-point: value = real_value * 65536
- 1.0 meter = 32'h00010000
- cos/sin values pre-computed or approximated
- Broom tip calculation: tip_x = x + cos(r), tip_y = y + sin(r)
- Collision detection: check line segment intersection between all pairs
- Use state machine: IDLE → PREPARE_TIPS → CHECK_COLLISIONS → DONE
- Latency: 16 clock cycles after start asserted

Line Segment Intersection Logic:
Two line segments (p1,q1) and (p2,q2) intersect if:
1. orient(p1,q1,p2) * orient(p1,q1,q2) <= 0
2. orient(p2,q2,p1) * orient(p2,q2,q1) <= 0
where orient(a,b,c) = cross((b-a), (c-a))

Cross product in 2D: (b_x-a_x)*(c_y-a_y) - (b_y-a_y)*(c_x-a_x)

Module should:
1. Calculate all 4 broom tip positions (use combinatorial logic for cos/sin approximation)
2. Store endpoints as registers
3. Check all 6 possible witch pairs: (0,1), (0,2), (0,3), (1,2), (1,3), (2,3)
4. If any pair intersects, set crash=1
5. Return done=1 when complete

For cos/sin approximation, you may use:
- Pre-computed values for common angles
- Or approximate using small lookup table
- Or simplify by checking intersection between pivot-to-tip segments directly

The module must handle:
- Fixed-point arithmetic for all calculations
- Overflow prevention (use 48-bit intermediate results for cross product)
- Proper state transitions
- Reset clears all registers
