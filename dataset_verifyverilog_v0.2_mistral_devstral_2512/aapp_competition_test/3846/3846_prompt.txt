Design a sequential Verilog module named 'leader_determiner' that identifies which team members can be the leader based on meeting log events. 

The leader must be present whenever anyone is present. A person can be a leader if they were not present during any 'gap' in attendance (periods where they were logged off while others were logged on).

Parameters:
- N: Number of participants (max 8)
- M: Number of log messages (max 16)

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [3:0] msg_id // Participant ID for current message (1 to N)
input msg_type // 0 for log off ('-'), 1 for log on ('+')
input msg_valid // High when current message is valid

Outputs:
output reg [N-1:0] possible_leaders // Bitmask of potential leaders
output reg done // High when computation is complete

Behavior:
1. Initialize with all participants as potential leaders.
2. Process messages sequentially.
3. Track active participants (logged on but not logged off).
4. Track 'gaps' for each participant: a gap occurs if participant X is logged off while 'active' is non-zero.
5. If a participant has a gap, they cannot be the leader.
6. Output bitmask of remaining valid leaders after processing all messages.

Specify latency: Result valid M clock cycles after start asserted.
Use state machine with states: IDLE, LOAD_MSG, PROCESS_MSG, UPDATE_STATE, DONE.
