Design a sequential Verilog module named 'train_sorter' that computes the minimum number of moves to sort a train of cars.

Problem Analysis:
- Given a permutation of cars numbered 1 to N
- In one move, a car can be teleported to the beginning or end
- Goal: Find minimum moves to sort the train

Algorithm Insight:
- The minimum moves equals N minus the length of the longest contiguous subsequence where car numbers are in increasing order
- For example: [4, 1, 2, 5, 3] -> The longest such subsequence is [1, 2, 5] with length 3, so moves = 5 - 3 = 2

Module Specification:
- N = 16 (fixed maximum size)
- Input: A permutation of 1 to 16
- Output: Minimum moves required

Module Interface:
module train_sorter (
    input clk,
    input rst_n,
    input start,
    input [15:0] p_in,      // Current car number (1-16) being input
    input [3:0] idx_in,     // Index of current car (0-15)
    output reg [3:0] result, // Minimum moves (0-15)
    output reg done         // Computation complete
);

Behavior:
1. Sequential FSM: IDLE -> PROCESSING -> DONE
2. On start, receives 16 input values sequentially
3. Internally maps: pos[value-1] = position of that car
4. Finds longest contiguous sequence 1,2,3... where pos is increasing
5. Result = 16 - longest_sequence_length

Latency: 18 clock cycles after start (16 to load + 2 to compute)

Parameters:
- N = 16
- Data width: 4 bits (for values 1-16)
- Index width: 4 bits (for positions 0-15)
- Result width: 4 bits (moves 0-15)

States:
- IDLE: Wait for start signal
- LOAD: Receive 16 values, store positions
- COMPUTE: Find longest increasing subsequence
- DONE: Output result

The module should be synthesizable and use reasonable hardware resources.
