Design a sequential Verilog module named 'packet_solver' that calculates the minimum number of packets needed to form any amount up to n.

The problem logic: For any integer n, the minimum number of packets is the number of bits in the binary representation of n. For example, n=6 (binary 110) requires 3 packets.

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [15:0] n // The number of coins (scaled down from 10^9 to fit 16 bits)

Outputs:
output reg [4:0] result // Minimum number of packets (max 16 for 16-bit input)
output reg done // High when computation complete

Specification:
- The module should implement an iterative algorithm to find the bit length of n.
- Algorithm: Initialize count = 0. While n > 0, increment count and right-shift n (divide by 2).
- Since this is hardware, use a state machine with states: IDLE, CALCULATING, DONE.
- In CALCULATING state, check if n is non-zero. If so, increment result and shift n right by 1.
- Latency: Result valid 18 clock cycles after start asserted (worst case 16 shifts + 2 overhead).
- Use non-blocking assignments for state transitions.
