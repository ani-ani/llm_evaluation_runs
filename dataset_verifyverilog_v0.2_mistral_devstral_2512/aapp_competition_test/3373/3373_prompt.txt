Design a sequential Verilog module named 'balanced_parentheses_solver' that finds the maximum length of balanced parentheses sequence from a set of pieces.

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [5:0] num_pieces // number of pieces (0-8)
input [7:0][15:0] pieces // up to 8 pieces, each 16 chars (use 2 bits per char: 01='(', 10=')', 00=padding)

Outputs:
output reg [9:0] max_length // maximum balanced length (0-1024)
output reg done // high when computation complete

Specification:
- Each piece is 16 characters, encoded as 2-bit values: 2'b01='(', 2'b10=')', 2'b00 or 2'b11=padding
- Process all subsets of pieces using a state machine
- For each subset, compute if it can form a valid balanced sequence
- Track maximum length achieved
- Use greedy approach: sort pieces by their balance properties, then DP

States: IDLE, PARSE_PIECES, EVALUATE_SUBSETS, COMPUTE_BEST, DONE
Latency: Max 512 clock cycles (2^8 subsets × few cycles each)

For each piece, compute:
- min_prefix: minimum balance (negative means needs '(' before)
- final_balance: net balance after processing whole piece
- total_len: length of piece

Algorithm (high-level):
1. Parse all pieces to get (min_prefix, final_balance, length)
2. Sort pieces by some ordering (not required in HW, use greedy selection)
3. For each subset, simulate concatenation:
   - Track current balance
   - If balance goes negative, subset is invalid
   - If valid, add to length
4. Return max valid length

Use Q4.4 fixed-point if needed, but mostly integer arithmetic.
Output: integer length.
