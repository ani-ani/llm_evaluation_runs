Design a sequential Verilog module named 'digit_distance_sum' that calculates the sum of digit-wise absolute differences for all pairs of numbers in a range [A, B], where A and B are 8-digit numbers (0-99,999,999).

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [31:0] A // starting number (8 decimal digits max)
input [31:0] B // ending number (8 decimal digits max)

Outputs:
output reg [31:0] result // final sum modulo 1000000007
output reg done // high when computation complete

Latency: Result valid approximately 600 clock cycles after start is asserted (for worst case range size).

Algorithm Description:
The module must compute: sum_{i=A}^{B} sum_{j=A}^{B} distance(i, j)
where distance(i, j) = sum_{k=0}^{7} |digit_k(i) - digit_k(j)|

For each of the 8 digit positions (0=units, 7=MSD), the contribution to the total sum is independent.

For a given digit position, let count[d] = number of numbers in range [A, B] that have digit d at this position.
Then the contribution of this position to the total sum is:
sum_{d1=0}^{9} sum_{d2=0}^{9} count[d1] * count[d2] * |d1 - d2|

The module should:
1. Use a state machine (IDLE, CALCULATE_COUNTS, CALCULATE_DISTANCE, COMPLETE)
2. Iterate through each digit position (0 to 7)
3. For each position, count digit frequencies across the range
4. Compute the distance contribution using nested loops d1=0..9, d2=0..9
5. Accumulate contributions with modulo 1000000007
6. Handle range [A, B] where B >= A

Implementation details:
- Counting digit frequencies requires iterating through the range
- Since range can be large (up to 10^8 values), use digit DP approach or simplified counting
- For simplicity, implement a loop that iterates from A to B (max 800k iterations for small ranges, or limit to 10,000 iterations for testability)
- Use 32-bit arithmetic throughout
- All additions should use modulo 1000000007 (0x3B9ACA07)
- The distance calculation can be optimized: for each digit position, compute sum_{d} count[d] * (sum_{d'} |d-d'| * count[d'])

State Machine:
- IDLE: Wait for start signal
- CALCULATE_COUNTS: Initialize digit count arrays for each position
- CALCULATE_DISTANCE: Compute distance contributions for each position
- COMPLETE: Set done flag and output result

The module should handle:
- Single number case (A=B): result should be 0
- Small ranges
- Range spanning multiple digits

Use registers for digit counts (8 positions × 10 digits = 80 counters).
Each counter can be 20 bits (max count 1,048,576 for 8-digit range).

The distance calculation should:
For each position (0 to 7):
  For digit d1 from 0 to 9:
    For digit d2 from 0 to 9:
      contribution += count[d1] * count[d2] * |d1 - d2|
  Add to total result (mod 1000000007)

Optimization: Pre-compute the distance weights for digits 0-9.
The distance sum for a set of digit counts can be computed as:
For digit d: its total distance contribution = count[d] * sum_{other_d} |d - other_d| * count[other_d]

Total states needed: IDLE, SETUP, COUNT_LOOP (for each number in range), COMPUTE_DIST (for each digit pos and digit pair), DONE.

The loop limit for range iteration should be parameterizable (e.g., MAX_ITER = 10000) to ensure testability.

Note: For exact handling of the full problem with arbitrary A and B, a digit DP approach would be needed. For this hardware module, we implement a practical version that can handle ranges up to reasonable size within feasible latency.
