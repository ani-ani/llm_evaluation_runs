Design a combinational Verilog module named 'traveling_salesman' that solves the traveling salesman problem for small DAGs with up to 4 cities.

Module Interface:
- Inputs:
  * n [3:0]: number of cities (1-4)
  * m [3:0]: number of train lines (0-6)
  * edges [5:0][5:0]: array of 6 edges. Each edge is 6 bits: [5:4]=source (0-3, city 1-4), [3:2]=dest, [1:0]=unused (must be 0)
- Outputs:
  * min_flights [1:0]: minimum flights needed (0-3)
  * airports [3:0]: bitmask of cities whose airports can be visited (bit 0=city1)

Algorithm:
1. Build bipartite graph: left nodes = sources, right nodes = destinations
2. Find maximum matching size by enumerating all 64 edge subsets
3. min_flights = (n - 1) - max_matching_size
4. If min_flights == 0: airports = 0
5. Else: find all cities that can be unmatched in some max-matching (left or right), set corresponding bits in airports

Implementation Notes:
- Use combinational logic only (no clock)
- For matching enumeration: for each subset (0-63), check if it's a valid matching (no shared left/right nodes)
- Track maximum size and which cities can be unmatched in any matching of that size
- Handle case when n < 4 by ignoring unused cities
- Cities are 1-indexed in input, but 0-indexed internally (city 1 = index 0)
