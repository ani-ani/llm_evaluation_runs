Design a combinational Verilog module named 'quadrilateral_game_score' that computes the total score sum for the described game.

Problem Adaptation:
- Input: N=8 fixed points with coordinates (x, y), x and y range from -100 to 100 (scaled from original -10^6)
- Each quadrilateral is a unique set of 4 distinct points
- The area of a quadrilateral (or polygon) can be computed using the Shoelace formula via cross products
- 2 * Area = |Sum of cross products of adjacent vertices|
- Since no three points are collinear, all quads have non-zero area
- Game Theory: Since players play optimally to maximize their own score and all quadrilaterals are distinct choices, the total score is the sum of 2*Area of all possible unique quadrilaterals (combinations of 4 points).

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input signed [11:0] x_i [0:7] // 8 points, x coordinates (signed 12-bit, range -2048 to 2047)
input signed [11:0] y_i [0:7] // 8 points, y coordinates (signed 12-bit)

Outputs:
output reg [31:0] total_score // Sum of 2*Area of all quadrilaterals modulo 1000003
output reg done // High when computation complete

Module Behavior:
1. Iterate through all unique combinations of 4 points (70 combinations for N=8: C(8,4)=70)
2. For each combination (A, B, C, D), compute 2*Area using cross products.
   - Shoelace formula: 2*Area = |(x1*y2 - x2*y1) + (x2*y3 - x3*y2) + (x3*y4 - x4*y3) + (x4*y1 - x1*y4)|
3. Accumulate these values into total_score, applying modulo 1000003 at each addition.
4. Use a state machine: IDLE, LOAD_POINTS, CALCULATE_LOOP, DONE.
5. Use nested loops or counters to generate the 4-tuple indices (0,1,2,3), (0,1,2,4)... etc.
6. Latency: Since 70 quads take 70 cycles to compute + overhead, result is valid ~100-150 cycles after start.

Constraint: Fixed N=8. The module should be unrolled or iterated over the combinations.
