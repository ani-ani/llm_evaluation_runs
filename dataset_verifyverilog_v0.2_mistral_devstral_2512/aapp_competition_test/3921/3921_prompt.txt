Design a sequential Verilog module named 'good_sequence_solver' that computes the length of the longest good sequence.

A sequence is good if:
1. Strictly increasing
2. Adjacent elements are not coprime (share a prime factor > 1)
3. All elements are from the input list

Constraints:
- Input size N ≤ 16
- Input integers a_i ≤ 256 (scaled from original 10^5)
- Prime factors limited to primes ≤ 256

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [3:0] n // Number of input integers (1 to 16)
input [15:0] a [0:15] // Input array of 16 fixed-width values

Outputs:
output reg [7:0] result // Length of longest good sequence (max 16)
output reg done // High when computation complete

Specifications:
- Latency: Result valid ~30 clock cycles after start asserted
- Use state machine: IDLE, READ_PRIMES, CALCULATE_DP, UPDATE_RESULT, DONE
- Pre-compute prime factors for input values (store in LUT)
- DP state: Track max sequence length for each prime factor (primes up to 256)
- Update rule: For each input, find max sequence length among its prime factors, then update all its prime factors
- Output max length found

Module Behavior:
1. IDLE: Wait for start signal
2. READ_PRIMES: For current input a[i], determine its prime factors (using pre-stored LUT)
3. CALCULATE_DP: Find max(dp[p]) for all prime factors p of a[i]
4. UPDATE_RESULT: Set dp[p] = max + 1 for all prime factors p of a[i]
5. DONE: Output the global maximum and assert done

Implementation Details:
- Define a parameter MAX_PRIME = 256
- DP array: reg [7:0] dp[0:255] (store length for each prime)
- Use a secondary LUT for prime factors of small integers (e.g., array of 256 entries, each entry is 4-bit mask or actual prime list)
- For this task, assume input values are limited and prime factor lookup can be done via combinational logic or small ROM
