Design a sequential Verilog module named 'lucky_permutation' that generates Lucky Permutation Trips for small odd values of n.

PROBLEM BACKGROUND:
A Lucky Permutation Triple consists of three permutations a, b, c of length n where for all i: (a[i] + b[i]) % n == c[i]. It exists only for odd n, using the construction a[i]=i, b[i]=i, c[i]=(2*i)%n.

MODULE SPECIFICATION:
- Module: lucky_permutation
- Parameters: MAX_N = 16 (maximum permutation length)
- Clock: clk, Active-low reset: rst_n
- Input: start (pulse to begin computation)
- Input: n_in [7:0] (length of permutation, 1-16)
- Output: a_out [3:0] (current element of permutation a)
- Output: b_out [3:0] (current element of permutation b)
- Output: c_out [3:0] (current element of permutation c)
- Output: index_out [3:0] (current index 0 to n-1)
- Output: valid (high when outputs are valid)
- Output: done (high when all n elements are computed)

BEHAVIOR:
1. IDLE state: Wait for start pulse
2. PROCESSING state: Compute a[i]=i, b[i]=i, c[i]=(2*i)%n for i from 0 to n-1
   - Use a counter to track current index
   - Compute c = (2*i) % n using modulo operation
   - Output each triple (a[i], b[i], c[i]) with valid=1
   - Advance index each clock cycle
3. DONE state: Set done=1, valid=0

LATENCY: n + 2 cycles (1 for reset/setup, n for computation, 1 for done)

IMPLEMENTATION NOTES:
- Use finite state machine with 3 states: IDLE, PROCESSING, DONE
- For modulo by n (odd), can use repeated subtraction or bitwise logic for powers of 2
- Since n≤16, c[i] = (2*i) % n can be computed: if (2*i < n) c=2*i, else c=2*i-n
- Outputs are 4-bit since n≤16
- Must handle n=1 as special case

OUTPUT FORMATTING:
The module outputs one triple per clock cycle when valid=1. The index_out increments from 0 to n-1. The testbench will collect all outputs and verify:
- a[i] = i
- b[i] = i
- c[i] = (2*i) % n
- All three are permutations (each value 0 to n-1 appears exactly once)

EDGE CASES:
- n is even: Should never be called (problem constraint: only odd n inputs)
- n=1: a[0]=0, b[0]=0, c[0]=0
- n=3: outputs (0,0,0), (1,1,2), (2,2,1)

The module should be purely sequential, using a state machine to iterate through the permutation generation.
