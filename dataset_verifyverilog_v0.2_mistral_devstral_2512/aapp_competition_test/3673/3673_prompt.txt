Design a sequential Verilog module named 'dance_solver' that reconstructs the arrow placement (functional graph P) given the result of K moves (permutation A) and K itself. 

Problem Context: 
We are given N dancers and N marks. After K moves, the permutation A maps original dancer i to position a_i (where dancer a_i ends up). We need to find permutation P (arrows) such that P^K = A.

Constraints:
- N <= 8 (Maximum number of dancers)
- K <= 255 (Maximum number of moves)
- All inputs are integers.

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [7:0] N // Number of dancers (2-8)
input [7:0] K // Number of moves (1-255)
input [7:0] A_in [0:7] // Input permutation A (0-indexed values, range 0 to N-1). The input is a flattened array representing the permutation A.

Outputs:
output reg [7:0] P_out [0:7] // Output permutation P (0-indexed values). P[i] = j means arrow from i to j.
output reg done // High when computation is complete
output reg possible // High if solution found, low if impossible

Behavioral Description:
The module should implement the following algorithm:
1. Decompose the input permutation A into disjoint cycles. Example: A = [2,3,0,1] for N=4 has cycles [0->2->0] and [1->3->1].
2. For each cycle in A with length L:
   - Calculate G = gcd(L, K).
   - This cycle of length L in A corresponds to G cycles of length M = L/G in P.
   - To find P, we need to determine the shift within the preimage cycle.
   - Let the cycle in A be (c_0, c_1, ..., c_{L-1}) where c_{i+1} = A(c_i).
   - We want to find P such that P^K = A.
   - For a single element x = c_0 in A, let its position in the P-cycle be p_0.
   - We have (c_0) -> (c_1) -> ... -> (c_{L-1}) -> (c_0).
   - In P, we go from x -> ... -> x.
   - We need to link the elements such that K steps in P equal 1 step in A.
   - A naive approach for reconstruction: 
     For a cycle C in A of length L, let the indices be c_0, c_1, ..., c_{L-1}.
     We know that P^K (c_i) = c_{(i+1)%L}.
     If G = gcd(L, K), then the cycle in P will be of length L' = L / G.
     We need to group the A-cycle elements into G disjoint P-cycles.
     A cycle in P looks like: x_0 -> x_1 -> ... -> x_{L'-1} -> x_0.
     Applying P^K: x_0 -> x_{K mod L'} -> ...
     We need (P^K)(x_0) = A(x_0).
     Let's use the standard inversion method:
     Iterate through all unassigned elements in A.
     Start a cycle in P from an unassigned element x.
     We need to find the predecessor of x in P, call it y, such that P(y) = x.
     Since P^K(x) = A(x), P must map elements to elements such that after K hops we reach A(x).
     A simpler constructive approach for P:
     Iterate i from 0 to N-1.
     If A[i] is not part of a P-cycle yet:
       Start a new P-cycle.
       Let curr = i.
       Let path = []
       While curr is not in path:
         Add curr to path.
         We need to find prev such that P^K(prev) = curr.
         Wait, that's hard to construct directly.
         
         Correct Logic for P:
         We want P such that P^K = A.
         Let's construct P by iterating through A's cycles.
         For each cycle in A: c_0 -> c_1 -> ... -> c_{L-1} -> c_0.
         Let L be the length. G = gcd(L, K). M = L/G.
         The elements of this A-cycle will be split into G cycles in P.
         Let the offset be determined by the index in the cycle.
         For g in 0 to G-1:
           Start a P-cycle with element c_g.
           The next element in P should be the element that maps to c_g after K steps.
           P(c_g) = c_{(g + K) % L}? No.
           P^K(x) = A(x).
           If we map c_g -> c_{(g + K) % L} -> ...
           After K steps: c_g -> c_{(g + K) % L}.
           So if P(c_g) = c_{(g + K) % L}, then P^K(c_g) = c_{(g + K*K) % L}. This is wrong.
           
           Let's define P on the cycle indices.
           We have indices 0 to L-1. We want a shift s such that (i + s) mod L, applied K times, gives i+1 mod L.
           i + K*s = i + 1 (mod L) => K*s = 1 (mod L).
           This only works if gcd(K, L) = 1. If not, we can't map the whole cycle to one P-cycle.
           
           If G > 1:
           The cycle in A (length L) consists of G interleaved cycles in P (length M=L/G).
           The elements of the P-cycle starting at c_g are: c_g, c_{g+K}, c_{g+2K}, ...
           This generates the cycle: c_g, c_{g+K}, c_{g+2K}, ..., c_{g+(M-1)K}.
           All indices mod L.
           Since K*M = K*(L/G) = (K/G)*L, which is 0 mod L, the cycle length is M.
           
           So the algorithm is:
           1. Find cycles of A.
           2. For each cycle (c_0, ..., c_{L-1}):
              G = gcd(L, K)
              M = L / G
              For offset = 0 to G-1:
                 For j = 0 to M-1:
                   curr = c[(offset + j*K) % L]
                   next = c[(offset + (j+1)*K) % L]
                   Set P[curr] = next
           
           This maps the cycle elements to P-cycles.
           
3. Verification: Check if the constructed P satisfies P^K == A.
   
Implementation details:
- Use combinational logic for gcd and cycle decomposition.
- Use a state machine to iterate through N.
- Store P in a register array.
- Store cycle decomposition in local memory.
- Output P_out.

Latency: Approx 50-100 cycles depending on N and K computation.
States: IDLE, PREPARE (find cycles), COMPUTE_P (construct P), VERIFY, DONE.
