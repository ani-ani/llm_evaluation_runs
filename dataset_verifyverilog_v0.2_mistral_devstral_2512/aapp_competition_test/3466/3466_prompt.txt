Design a sequential Verilog module named 'sweet_diet' that determines how many more sweets Danny can buy while maintaining a balanced diet.

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [2:0] m // number of sweet types (1-8)
input [15:0] a [0:7] // target fraction numerators (sum <= 1000)
input [15:0] s [0:7] // current counts of each type
input [15:0] n // total sweets eaten so far

Outputs:
output reg [15:0] additional_count // number of additional sweets possible
output reg forever_flag // high if can continue indefinitely
output reg done // computation complete

Behavior:
The module implements a bounded simulation (max 256 steps) to determine how many more sweets can be bought.

1. Convert fractions to Q16.16 fixed-point: f_i = (a_i * 65536) / sum_a
2. At each step, for each type i, check if buying it maintains balance:
   - New n' = n + 1
   - New s_i' = s_i + 1
   - For all j: n'*f_j - 1 < s_j' < n'*f_j + 1
3. If any type can be bought, increment count and repeat
4. If no type can be bought, stop and output count
5. If count reaches 256, set forever_flag high

Use state machine states: IDLE, CHECK_BALANCE, UPDATE_COUNT, DONE

Compute balance check using Q16.16 arithmetic with proper scaling.
Latency: approximately 256 * 8 clock cycles worst case.
