Design a combinational Verilog module named 'oven_decision' that determines if building a second oven is beneficial based on the provided game logic.

Inputs:
input [15:0] n // Number of cakes needed
input [15:0] t // Time to bake k cakes (minutes)
input [15:0] k // Number of cakes baked per batch
input [15:0] d // Time to build the second oven (minutes)

Outputs:
output build_second // 1 if YES (beneficial), 0 if NO

Behavioral Description:
The module calculates the decision in two steps:
1. Calculate the time needed with only one oven:
   - Determine the number of batches required: batches = ceil(n / k)
   - In hardware, ceil(a/b) can be calculated as (a + b - 1) / b using integer division.
   - single_time = batches * t

2. Calculate the time needed if the second oven is built:
   - The first oven runs continuously for 'd' minutes while the second is built.
   - Cakes baked during construction = floor(d / t) * k
   - Remaining cakes needed = n - cakes_baked_during_construction
   - If remaining cakes <= 0, construction finishes after 'd' minutes, but since d >= 0, total time is at least d.
   - If remaining > 0, after 'd' minutes, both ovens work together. The effective rate doubles. However, calculating exact end time is complex. 
   - Alternative check: If the single oven finishes strictly before the second oven would be ready (or just as it becomes ready), it's not worth it.
   - Specifically, if `single_time <= d + t`, then the second oven doesn't help because the first oven would have finished or just finished by the time the second one could complete its first batch.
   - If `single_time > d + t`, it is beneficial.

Logic:
- batches = (n + k - 1) / k
- single_time = batches * t
- Condition: single_time > d + t
- If true, output 1, else 0.
