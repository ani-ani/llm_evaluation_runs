Design a sequential Verilog module named 'array_debug' that implements a simplified version of the array update and range sum query problem.

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start the entire operation (process updates then queries)
input [5:0] k_val // number of updates (0-32)
input [5:0] q_val // number of queries (0-32)
input [5:0] update_val // current update jump value (valid when processing updates)
input update_valid // high when update_val is valid
input query_l, query_r // current query bounds (valid when processing queries)
input query_valid // high when query_l and query_r are valid

Outputs:
output reg [31:0] result // the sum for the current query
output reg done // high when all queries are processed
output reg ready_for_update // high when ready to accept next update
output reg ready_for_query // high when ready to accept next query

Behavior:
1. When start is asserted, reset internal state.
2. Accept exactly k_val updates. For each update X, increment all array elements at indices divisible by X. Array size is fixed to 64 elements (indices 0-63).
3. After updates, compute prefix sums for the entire array. This should be done efficiently, perhaps using a pipelined adder tree to compute prefix sums P[i] = sum(seq[0]...seq[i]).
4. Accept exactly q_val queries. For each query (L, R), calculate the sum using prefix sums: sum = P[R] - P[L-1] (with P[-1] = 0). Output the result.
5. Use a state machine with states: IDLE, COLLECT_UPDATES, PROCESS_UPDATES, BUILD_PREFIX, COLLECT_QUERIES, PROCESS_QUERIES, DONE.

Constraints:
- Array size is 64 elements (indices 0-63).
- Maximum K is 32.
- Maximum Q is 32.
- Jump values X are between 1 and 63.
- The module should handle the handshake protocol for inputs and outputs.
- Latency: Result valid a few cycles after query valid is accepted (specify the latency based on your design).
