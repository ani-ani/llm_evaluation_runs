Design a sequential Verilog module named 'dog_feeding_optimizer' that computes the minimum total waiting time for feeding dogs.

Module interface:
module dog_feeding_optimizer(
  input clk, // clock signal
  input rst_n, // active-low reset
  input start, // pulse to start computation
  input [2:0] n, // number of dogs (2-4)
  input [2:0] m, // number of bowls (n <= m <= 6)
  input [7:0] eating_times_0_0, eating_times_0_1, eating_times_0_2, eating_times_0_3, eating_times_0_4, eating_times_0_5, // dog0 bowl times
  input [7:0] eating_times_1_0, eating_times_1_1, eating_times_1_2, eating_times_1_3, eating_times_1_4, eating_times_1_5, // dog1 bowl times
  input [7:0] eating_times_2_0, eating_times_2_1, eating_times_2_2, eating_times_2_3, eating_times_2_4, eating_times_2_5, // dog2 bowl times
  input [7:0] eating_times_3_0, eating_times_3_1, eating_times_3_2, eating_times_3_3, eating_times_3_4, eating_times_3_5, // dog3 bowl times
  output reg [9:0] result, // minimum total waiting time
  output reg done // high when computation completes
);

Behavior:
1. On start pulse, compute optimal bowl assignment for n dogs from m bowls.
2. Algorithm: checks all valid permutations (no bowl reuse) to find assignment that minimizes T = Σ(max_t - t_i).
3. Permutation space reduced using n-sequential counters (max 6×5×4×3 = 360 permutations for worst case n=4).
4. Output valid after ~1000 cycles max (done asserted).
5. Internal store for current best T and handled dogs.
6. All eating times are 8-bit unsigned (1-200) input directly from testbench.
7. Result T is 10-bit unsigned (max Σ(200×4)=800).

Latency: Variable (because not all permutations need to be tested), completion indicated by done signal.
