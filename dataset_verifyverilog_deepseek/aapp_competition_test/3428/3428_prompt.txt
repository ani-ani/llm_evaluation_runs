Design a sequential Verilog module named 'gcd_distinct_count' to compute the number of distinct contiguous-subsequence GCD values in a sequence of up to 8 elements, defined as follows:

Module interface:
module gcd_distinct_count(
  input clk, // system clock
  input rst_n, // active-low reset
  input start, // start computation
  input [2:0] n, // sequence length (1-8)
  input [7:0][15:0] a, // 8-element sequence (16-bit values)
  output reg [5:0] count, // number of distinct GCDs
  output reg done // high when computation completes
);

Behavior:
1. On reset or idle state, wait for start signal (level sensitive)
2. Compute all GCD values for contiguous subsequences (i to j where 0 ≤ i ≤ j < n)
3. Store GCDs in a 8x8 table (only uses lower triangular portion)
4. Calculate number of distinct GCD values in the table
5. Output final count with done signal (hold 1 cycle)

Implementation constraints:
- Use iterative GCD computation (Euclidean algorithm)
- Implement as 3-state FSM: IDLE, COMPUTE, COUNT
- Table dimensions 8x8 (64 entries) with valid flags
- Minimum 12-bit storage per GCD value (only 36 entries actually used)
- Result computed in ≤ 256 cycles after start asserted (max n=8)
- Use non-blocking assignments for sequential logic

Timing requirements:
- Start signal must be held high for at least 1 clock cycle
- Computation begins on next rising edge after start assertion
- Done signal asserts 256 cycles after computation start (worst case)

Example behavior (match Python test cases):
For n=4, a[7:0]={9,6,2,4,0,0,0,0} -> count=6
For n=4, a[7:0]={9,6,3,4,0,0,0,0} -> count=5
