Design a Verilog module named 'gem_collector' that calculates the maximum number of collectable gems under movement constraints.

Module interface:
module gem_collector(
  input clk, // 100MHz clock
  input rst_n, // active-low reset
  input start, // pulse high to start computation
  input [3:0] gem_count, // number of gems (1-8)
  input [3:0] r, // velocity ratio (1-10)
  input [7:0] w, // track width (0-255)
  input [7:0] h, // finish height (0-255)
  input [7:0] gem_x [0:7], // gem x coordinates (0-8\'d255)
  input [7:0] gem_y [0:7], // gem y coordinates (1-8\'d255)
  output reg [3:0] max_gems, // maximum collectable gems (0-8)
  output reg done // high when computation complete
);

Behavior:
1. On start pulse, module sorts gems by ascending y-coordinate (if needed)
2. Computes maximum gems via dynamic programming: for each gem i, check all earlier gems j where |x_i - x_j| <= (y_i - y_j)/r
3. Result available at \'max_gems\' output when \'done\' is high
4. Latency: Worst-case 128 cycles (8 gems * 16 comparisons)
5. Store gem order in internal memory after sorting

Implementation notes:
- Use state machine with states: IDLE, SORTING, CALCULATING, DONE
- Comparison logic should use 16-bit intermediates (max width: 8-bit + 8-bit/r x 256)
