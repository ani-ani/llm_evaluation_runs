Design a sequential Verilog module named 'table_counter' that implements a simplified version of the infinite table generation problem. 

The module must compute the sequence of values generated by the recurrence A(i, j) = A(i, j-1) + rev(A(i, j-1)), where rev(x) reverses the decimal digits of x.

Adaptation:
- We only consider starting values (rows) i from 1 to 16 (scaled from infinite).
- We only generate the first 16 columns (steps) for each row.
- We count how many generated values fall within a user-specified range [LOW, HIGH].
- Numbers are handled as integers (max value approx 1023 to fit in 10-12 bits).

Inputs:
input clk // Clock
input rst_n // Active-low reset
input start // High to start the calculation for a new query
input [9:0] query_low // Lower bound of the range to count
input [9:0] query_high // Upper bound of the range to count

Outputs:
output reg [15:0] count // The number of occurrences found
output reg done // High when calculation is complete for the current query

Behavior:
1. The module contains hardcoded logic (or small memory) for the first 16 values of each row (1 to 16). 
2. Ideally, it should generate values on the fly using a state machine to save resources, but a lookup table (LUT) for rows 1-16 is acceptable if unrolled.
3. However, to demonstrate sequential logic, use a single state machine that iterates through rows 1 to 16, and for each row, iterates columns 1 to 16, computing the sequence `current = current + rev(current)`.
4. `rev(current)` must be computed combinationally. Since max value is < 1024, `rev` handles up to 3 digits (e.g., 123 -> 321).
5. The state machine states should be: IDLE, FETCH_START (load i=1, val=i), COMPUTE_ROW (generate next val, check range), NEXT_ROW (increment row), DONE.
6. In IDLE, wait for `start`. When `start` is high, reset `count` to 0.
7. In COMPUTE_ROW, compute `next_val = val + rev(val)`. If `val` is in [query_low, query_high], increment `count`. Repeat 16 times for the row.
8. After 16 rows, go to DONE.
9. Result latency: approx 16*16 = 256 clock cycles.

Constraints:
- Input values `query_low` and `query_high` are 10-bit unsigned integers (range 0-1023).
- Intermediate values `val` and `next_val` should be 12-bit to be safe.
- The `rev` function must handle decimal reversal. Example: rev(12) = 21, rev(100) = 1.
- The module should output the total count of occurrences of any number generated by the process (in any row/column) that falls within the query range.

Example Trace:
Row 1: 1 -> 2 -> 4 -> 8 -> 16 -> 77 -> 154 -> ...
Row 5: 5 -> 10 -> 11 -> 22 -> 44 -> 88 -> 176 -> ...
If query is [5, 10], valid numbers are 5, 8, 10. 
Row 1 contains 8. Row 5 contains 5, 10.
Total count = 3. (Wait, looking at table: Row 1 has 1,2,4,8. Row 2 has 2,4,8. Row 5 has 5,10,11. Row 3 has 3,6,12. If range [5,10], valid numbers are 5,6,8,10. Occurrences: 5(1), 6(1), 8(2), 10(1). Total = 5. Note: The problem statement says 'how many appearances'.)

The module must work for any query range within 10 bits. The logic must be purely hardware synthesizable.
