Design a sequential Verilog module named 'pokemon_gcd' that implements a simplified algorithm to find the maximum number of Pokemon that can be taken without fighting.

The problem is adapted to find the prime factor that appears in the most Pokemon strengths. The module uses a lookup table for prime numbers and counts occurrences.

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [7:0] n // Number of Pokemon (max 8, scaled down)
input [7:0] pokemon_strength [0:7] // Array of 8 Pokemon strengths (values 1-255)

Outputs:
output reg [7:0] result // Maximum count of Pokemon sharing a common factor
output reg done // High when computation complete

Specifications:
- The module uses a sequential state machine to process inputs.
- Max input size N=8, values 1-255.
- Latency: Approximately 32 clock cycles after start asserted.
- States: IDLE, LOAD, COUNT_FACTORS, FIND_MAX, DONE.
- Use a fixed-size array `prime [0:31]` for primes up to 255 (2, 3, 5, 7, ...).
- Use a `count[0:31]` register array to count occurrences of each prime factor.
- Algorithm: 
  1. Wait for start.
  2. For each Pokemon strength, check divisibility by each prime in the list.
  3. Increment corresponding count if divisible.
  4. Find the maximum value in the count array.
  5. Output max count (minimum 1).
- Ensure that the result is valid only when done is high.
