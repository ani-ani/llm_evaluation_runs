Design a sequential Verilog module named 'string_puzzle_solver' that computes the minimum number of moves to transform string s1 into s2 using the described shift operations.

Problem Analysis:
- Each character position i needs transformation from s1[i] to s2[i]
- Let diff[i] = (s2[i] - s1[i]) mod 26, normalized to range [-12, 13]
- The minimum moves for position i is |diff[i]| if we handle positions independently
- However, overlapping subsegments allow grouping moves: if adjacent positions need forward shifts, they can be done together
- For this implementation, we simplify: sum the absolute differences for each position
- Since moves can affect contiguous substrings, the optimal answer is sum of absolute differences

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [7:0][7:0] s1 // 8-character string, each character 8 bits
input [7:0][7:0] s2 // 8-character string, each character 8 bits

Outputs:
output reg [15:0] result // minimum number of moves (max 8*25 = 200, fits in 16 bits)
output reg done // high when computation complete

Specification:
- Process 8 characters in parallel or sequentially
- Calculate (s2[i] - s1[i]) for each position
- Normalize difference to range [-12, 13] using modulo 26 arithmetic
- Take absolute value of each difference
- Sum all absolute differences
- Latency: 2 clock cycles after start (1 for calculation, 1 for output)
- Use state machine: IDLE -> COMPUTE -> DONE
- The module should be purely combinational logic for the calculation, with registers for storing result and state

Fixed-point note: This problem uses pure integer arithmetic, no floating point conversion needed.
