Design a sequential Verilog module named 'digit_sum_optimizer' that solves the problem of finding two integers a, b such that a + b = n and S(a) + S(b) is maximized, where S(x) is the sum of digits of x.

The core insight is that the optimal 'a' is typically of the form (digit-1) followed by many 9s. For example, for n=35, the optimal a is 29 (S=11), b=6 (S=6), total 17, or a=18 (S=9), b=17 (S=8), total 17.

However, a simpler hardware-friendly approach is to iterate through possible values of 'a' that are candidates: a = 0, 9, 99, 999, ... and also variations like 19, 29, ... but to keep it simple and correct for the small input range (max n < 4096), we will implement a state machine that iterates 'a' from 0 to n (limited to 12-bit range) and computes the digit sum of 'a' and 'n-a'. We will find the maximum.

Since n is small (max 4095), we can iterate 'a' from 0 to n. To be efficient, we'll use a state machine.

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation
input [11:0] n // The input integer n (0 to 4095)

Outputs:
output reg [7:0] result // Maximum S(a) + S(b)
output reg done // High when computation complete

Specify latency: Result valid approximately n+20 clock cycles after start asserted (since we iterate a from 0 to n). For n=4095, this is ~4100 cycles. Use state machine with states: IDLE, COMPUTE_A, COMPUTE_B, CHECK_MAX, DONE.

The module should:
1. Reset to IDLE state.
2. In IDLE, wait for 'start'.
3. Initialize a = 0, max_sum = 0.
4. Loop (state CHECK_MAX): if a > n, go to DONE.
5. Compute b = n - a.
6. Compute S(a) and S(b) using a digit-summing helper state machine (iterate through bits/decimal logic).
7. Update max_sum if S(a)+S(b) is larger.
8. Increment a by 1.
9. Repeat loop.
10. Output result and set done high.
