Design a sequential Verilog module named 'hanabi_solver' that computes the minimum number of hints required to distinguish a set of cards.

The game has 5 colors (R,G,B,Y,W) and 5 values (1-5). Hints are subsets of these 10 attributes. A hint set is valid if every pair of distinct cards differs in at least one hinted attribute (either color or value).

Inputs:
input clk // Clock signal
input rst_n // Active-low reset
input start // Start computation signal
input [4:0] unique_cards_count // Number of unique cards (scaled to max 16)
input [15:0] card_attributes [0:15] // Array of 16 cards, each 16-bit vector. Bits [4:0] are color mask, bits [9:5] are value mask. Only first 'unique_cards_count' entries are valid.

Outputs:
output reg [3:0] min_hints // Minimum number of hints found (0-10)
output reg done // High when computation complete

Behavior:
The module should implement a brute-force search over all 10-bit hint masks (from 0 to 1023). For each mask, it verifies if it distinguishes all valid cards (using bitwise AND operations). It keeps track of the minimum number of set bits (popcount) among valid masks.

Latency: Result valid approximately 1024 clock cycles after 'start' is asserted (one cycle per mask check).

Use a state machine with states: IDLE, PROCESSING, DONE.
In IDLE: Wait for start.
In PROCESSING: Iterate through mask 0 to 1023. For each mask, check all unique card pairs. If valid, update min_hints.
In DONE: Signal completion.

Note: The card_attributes input format is specific. Each card is represented as a 16-bit value where bit i (0-4) corresponds to color i and bit (i+5) corresponds to value i. For example, a Red-1 card would be 0000100001 (binary).
