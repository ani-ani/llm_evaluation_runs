Design a sequential Verilog module named 'gaggle_mentor' that finds the optimal mentor assignment for a small group of employees.

The problem: Given current mentor assignments for n employees (n ≤ 8), find a new assignment that:
1. Forms a single cycle (everyone can reach everyone)
2. Each employee has exactly one mentor
3. Minimizes changes for lower-numbered employees (prefer keeping current mentor, otherwise smallest possible new mentor)

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [2:0] n // number of employees (2-8)
input [7:0][7:0] current_mentor // current assignments, indexed by employee 0-7 (0 means none)
// Note: employees are numbered 1-8 in problem, mapped to 0-7 here

Outputs:
output reg [7:0] new_mentor // new assignment for current employee
output reg [2:0] employee_idx // which employee we're outputting (0-7)
output reg done // high when all assignments computed

Specify latency: 1000 cycles maximum after start asserted.

Behavior:
- Use a state machine with states: IDLE, FIND_BEST_CYCLE, OUTPUT_RESULTS, DONE
- In FIND_BEST_CYCLE state, systematically try all possible permutations that form cycles
- For each candidate cycle, evaluate its quality: compare to original assignment starting from employee 1
- Track the best cycle found
- In OUTPUT_RESULTS state, output the new assignment employee by employee
- The algorithm should find the lexicographically optimal cycle:
  * For employee i from 1 to n, prefer keeping current mentor
  * If must change, choose smallest possible mentor that maintains cycle property
  * Ensure all employees are in one cycle

Fixed-point: Not needed, use integer arithmetic.

Implementation guidance:
- Use lookup tables for cycle validation
- Implement lexicographic comparison logic
- Use bounded loops (max 8! iterations, but optimize with pruning)
- The module should be synthesizable and use reasonable resources

Note: This is a hardware adaptation of a graph algorithm problem, scaled down to make it feasible while preserving the core optimization challenge.
