Design a sequential Verilog module named 'min_cost_calculator' that computes the minimum cost M + N such that M * N = K, where M is the server capacity and N is the number of servers. The input K is given as a list of prime factors.

Inputs:
input clk // clock signal
input rst_n // active-low reset
input start // start computation
input [5:0] num_factors // number of prime factors (max 8)
input [7:0] prime_factors [0:7] // array of prime factors, each 8-bit

Outputs:
output reg [63:0] min_cost // minimum cost (M + N)
output reg done // high when computation complete

Latency: Result valid ~100 clock cycles after start asserted (depends on loop counts).

Behavioral Description:
The module needs to find a divisor D of K such that D + K/D is minimized. Since K can be large, we compute the product of all primes to get K. However, we need to find the divisor D. Since the number of factors is small (max 8), we can iterate through all subsets of the prime factors to form a divisor D.

Algorithm:
1. Receive the list of prime factors.
2. Calculate the total product K (accumulator).
3. Iterate through all possible subsets of the factors (using a counter from 0 to 2^num_factors - 1).
4. For each subset, calculate the product of factors in the subset to form a candidate divisor D.
5. Calculate the corresponding N = K / D.
6. Calculate cost = D + N.
7. Track the minimum cost found.
8. Output the minimum cost.

Since we cannot perform division easily on arbitrary large numbers, we can use the property: if D is a divisor, then N = K / D. Since we generate D from prime factors, we can simultaneously generate K by accumulating all factors, and for each subset, we can accumulate the factors NOT in the subset to form N directly, or simply calculate N = K / D using integer division (assume K fits in 64-bit for scaled down version).

State Machine: IDLE, ACCUMULATE_K, GENERATE_SUBSETS, CALCULATE_D, CALCULATE_N, CALCULATE_COST, UPDATE_MIN, DONE.

Use 64-bit arithmetic for K, D, N, and min_cost.
