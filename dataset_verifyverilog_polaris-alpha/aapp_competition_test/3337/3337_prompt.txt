Design a Verilog module named 'stack_operations' that processes up to 16 stack operations according to Mirko's game rules.

Inputs:
- clk (clock signal)
- rst_n (active-low reset)
- cmd_valid (indicates valid command input)
- op_type [1:0] (operation type: 0='a'=push, 1='b'=pop, 2='c'=count)
- v [3:0] (source stack index)
- w [3:0] (target stack index for 'c' operation)

Outputs:
- result [4:0] (popped value for 'b', common count for 'c')
- result_valid (pulses high for valid result)
- done (asserted after processing 16 steps)

Behavior:
1. Active-low reset initializes stack 0 (empty). All stacks can hold up to 16 elements (4-bit values).
2. On rising clock with cmd_valid:
   - Copy stack v to new stack i (i = current step 1-15)
   - For 'a': push step number i onto new stack
   - For 'b': pop and output top element from new stack
   - For 'c': calculate distinct common elements between new stack and stack w
3. Stack storage: 16 stacks with 16 elements each (16x16x4 bit storage).
4. 'result_valid' pulses high one cycle after 'b' or 'c' commands.
5. 'done' asserts after step 15 completes.
6. Use presence vectors (16-bit) for 'c' operations:
   - Generate by checking each stack element up to current top
   - Calculate common count using popcount(presence_i & presence_w)

Timing:
- Each operation completes in 1 clock cycle when cmd_valid is high
- Output valid one cycle after operation start
- Use non-blocking assignments for state updates
