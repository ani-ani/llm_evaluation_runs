Design a sequential Verilog module named 'gold_store_optimizer' that calculates the maximum number of gold stores Demetrios can visit before submersion.

Inputs:
input clk,                  // clock signal
input rst_n,               // active-low reset
input start,               // start processing (pulse high to begin)
input [3:0] n,             // number of stores (1 ≤ n ≤ 8)
input [15:0] t_i_0,        // store 0 round-trip time
input [15:0] h_i_0,        // store 0 height
input [15:0] t_i_1,        // store 1 round-trip time
... (repeat for stores 2-7)
input [15:0] t_i_7,
input [15:0] h_i_7

Outputs:
output reg [3:0] max_count, // maximum stores possible (0-8)
output reg done             // high when calculation complete

Behavior:
1. On reset or when start is low, module remains idle
2. When start pulses high:
   a. Sort all n stores by h_i (height) in ascending order
   b. Process stores in sorted order: accumulate t_i values while total ≤ current store's h_i
   c. max_count is number of stores where accumulated time ≤ store height
3. Latency: Result guaranteed valid within 100 clock cycles after start assertion
4. Use a state machine with states: IDLE, SORT, ACCUMULATE, DONE
5. Sorting implementation: Use ripple sort (modified bubble sort) for small number of elements
6. Processing must account: total_time += t_i only if (current_total + t_i) ≤ h_i for current store

Timing:
- Output valid within 100 cycles after start assertion
- Done signal remains high until next reset or start

Note: All heights and times are 16-bit unsigned integers. Algorithm preserves original problem's core logic.
