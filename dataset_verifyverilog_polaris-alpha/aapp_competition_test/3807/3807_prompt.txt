Design a sequential Verilog module named `greedy_block_tower` that computes the maximum number of blocks and corresponding volume X (≤ input m) for Limak's tower building problem.

Module interface:
module greedy_block_tower(
  input clk, // clock signal
  input rst_n, // active-low reset
  input start, // start computation
  input [15:0] m, // max volume (1 ≤ m ≤ 65535)
  output reg [7:0] block_count, // max number of blocks (max 128)
  output reg [15:0] volume_X, // optimal X value
  output reg done // high when computation completes
);

Behavioral description:
1. On reset or !start: Initialize volume_X <= 0, block_count <= 0
2. When start rises: Use greedy algorithm to compute:
   a. Find largest a where a³ ≤ current_remaining_volume (initially m)
   b. Subtract a³ from current volume
   c. Add 1 to block_count and add cube to volume_X
   d. Consider branch condition: If (a-1)³ is better use it
3. Implement state machine with 3 states:
   - IDLE: Wait for start
   - FIND_CUBE: Find current maximum cube by successive approximation (max 32 steps)
   - UPDATE: Subtract cube and update counters
4. Output done=1 when current_remaining_volume=0 or cannot add more blocks
5. Latency: Computes result in ≤ 128 clock cycles (1 per block)
6. Pipelining: Maximum cube calculation done via linear search (accept cubes ≤ 40 since 40³=64000 < 65535)

Constraints:
- All arithmetic uses 16-bit unsigned values
- No division/multiplication - cube calculation via LUT (a*a*a) in state machine
