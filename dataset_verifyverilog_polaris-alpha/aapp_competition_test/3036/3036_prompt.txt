Design a Verilog module named `dinner_experiences` that calculates the number of valid 3-course meal combinations.

Module interface:
module dinner_experiences(
  input clk,                      // clock signal
  input rst_n,                    // active-low reset
  input start,                    // assert high to start computation
  input [2:0] r,                  // number of ingredients (max 8)
  input [2:0] s, m, d,           // courses: starters/mains/desserts (max 2)
  input [1:0] n,                  // incompatible pairs (max 2)
  input [1:0] brands [0:7],       // brand counts per ingredient (4-bit values)
  input [4:0] dish_ingredients [0:5][0:7], // [s+m+d x max_ingredients] dishes (max 6 dishes total)
  input [4:0] incompatible [0:1][0:1],     // incompatible pairs [n x 2]
  output reg [63:0] result,       // 64-bit result ('too many' is 1e18 threshold)
  output reg done                 // high when computation complete
);

Behavioral description:
1. The module shall sequentially iterate through all possible starter (s), main (m), and dessert (d) combinations (max 2x2x2=8 combinations).
2. For each combination, check against incompatible pairs database (n <= 2 pairs).
3. For valid meal combinations:
  - Collect union of ingredients across all three dishes
  - Multiply brand counts for each unique ingredient
  - Accumulate total experiences
4. If total experiences exceed 1e18 during computation, immediately output 1e18 and set done.
5. Implement a state machine with states: IDLE, COMB_CHECK, BRAND_CALC, DONE.
6. Latency: Worst-case (8 combinations * 3 cycles) + 2 cycles reset = 26 cycles. Output valid 26 cycles after start.
7. Use 64-bit arithmetic throughout to prevent overflow during accumulation.
