Design a Verilog module named 'priority_scheduler' that implements a scaled-down Priority Ceiling Protocol for up to 4 tasks and 4 resources. The module should accept task configuration via registers upon initialization and output completion times.
Module interface:
module priority_scheduler(
  input clk, // Clock signal
  input rst_n, // Active-low reset
  output reg [7:0] task_complete [0:3] // Completion times for 4 tasks (8-bit time values)
);

Behavioral description:
1. Supports max 4 tasks and 4 resources with hardcoded configuration
2. Maintains:
   - Current processor time (8-bit counter)
   - Per-task state: instruction pointer, current priority/resources owned
   - Per-resource status: owner and priority ceiling
3. Each clock cycle:
   a. Identify running tasks (start_time <= current time)
   b. Compute blocking status and current priorities
   c. Execute next instruction of highest priority non-blocked task
   d. Increment clock by 1 if compute executed or no valid task
   e. Update task states/completion times
4. Marks task complete when all instructions executed
5. Outputs completion times when all tasks finish
Parameters:
- Task priorities: 2 bits (max 4 unique priorities)
- Resources: 2 bits ID
- Processor clock: 8 bits (0-255 microsecond range)
