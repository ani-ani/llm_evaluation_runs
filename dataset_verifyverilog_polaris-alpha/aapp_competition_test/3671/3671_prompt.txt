Design a sequential Verilog module named job_scheduler that calculates maximum cookies from up to 8 job offers.

Inputs:
input clk              // clock
input rst_n           // active-low reset
input start           // pulse high to start processing
input [2:0] job_count // number of jobs (1-8)
input [31:0] job_times [7:0] // array of timestamps (ms), unsorted

Outputs:
output reg [5:0] total_cookies // max cookies earned (0-32)
output reg done               // high when result ready

Behavior:
1. Module should first sort the job_times array in ascending order (only first job_count elements)
2. Implement modified scheduling algorithm with these steps:
   a. Initialize max_cookies[0] = 0
   b. For each job i from 0 to N-1:
      i. Find last job j where job_time[i] >= job_time[j] + 400,000
      ii. max_cookies[i] = max(max_cookies[i-1], cookies[i] + max_cookies[j])
3. Each job contributes cookies: 2 (small), 3 (medium), or 4 (humongous)
   - Assume all jobs use humongous (4 cookies) for maximum; ignore type selection

Timing:
- 80 clock cycles latency from start pulse to done assert
+ 10 cycles: sorting
+ 64 cycles: scheduling
+ 6 cycles: margin
- Output remains stable until next start pulse

Implementation Notes:
- Use parallel comparators for finding compatible jobs
- Store intermediate results in register array
- Assume job durations are 400000ms (4 cookies) for all jobs
- Treat array indices 0 to job_count-1 as valid
- Input time values guaranteed non-overlapping after processing
