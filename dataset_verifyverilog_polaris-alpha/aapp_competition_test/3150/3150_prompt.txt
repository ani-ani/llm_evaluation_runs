Design a sequential Verilog module named 'guard_placement_calc' that calculates the number of valid guard placements.

Inputs:
  input clk,             // clock
  input rst_n,           // active-low reset
  input start,           // start computation when high for 1 cycle
  input [4:0] num_trenches, // number of trenches (1-16)
  input [15:0][39:0] trenches, // packed trench data (16 max) - each trench: [39:36] x1[9:0], [35:32] y1[9:0], [31:28] x2[9:0], [27:24] y2[9:0] (each coordinate 10 bits)

Outputs:
  output reg [15:0] result_count, // number of valid placements (16-bit)
  output reg done           // high when computation complete

Behavior:
1. Stores trench endpoints internally when start is asserted
2. Calculates the number of valid guard triplet placements where:
   - All three guards must be on different trenches
   - All three must lie on the same straight line formed by some trench
3. State machine with states: IDLE, LOAD, PROCESS, DONE
4. Processes at 1 combination per clock cycle in PROCESS state
5. Latency: Maximum 560 cycles (C(16,3) combinations) + 2 cycles overhead
6. Output 'done' goes high when calculation completes.

Key specifications:
- Use 10-bit coordinates (0-1000)
- Represent lines parametrically for colinearity checks
- Skip duplicate trench selections (ensure i < j < k)
- Output should match test cases for given examples.
