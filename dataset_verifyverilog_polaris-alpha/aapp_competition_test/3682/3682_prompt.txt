Design a Verilog module named 'code_match_detector' that detects longest consecutive line matches between an input code snippet and up to 2 repository fragments. 

Module interface:
module code_match_detector(
  input clk, 
  input rst_n, 
  input start, 
  input [127:0] line_in, // 16 characters (8 bits per char)
  input line_valid, 
  input fragment_end, 
  output reg [2:0] max_count, // Maximum match count (0-4)
  output reg [255:0] filenames, // 2x128-bit filenames
  output reg done
);

Behavior:
- Sequential module with 3 states: IDLE, PROCESSING, DONE
- On start pulse: reset all internal registers
- Repository fragment storage: 2 fragments x 4 lines x 128 bits
- Each line is normalized (collapse whitespace, trim) before storage
- Compare input code lines against all fragment lines
- Track current consecutive match count per fragment
- After ***END***, output longest match count and filenames
- Latency: 1 cycle per line + 1 cycle for final calculation
- Max_count=0 if no matches

Normalization rules:
1. Remove leading/trailing spaces
2. Collapse consecutive spaces to single space
3. Skip empty lines after normalization

Storage constraints:
- Store first 2 fragments with first 4 non-empty lines each
- Filenames truncated to 16 characters (store as 128-bit values)

Output format:
- max_count: number representing longest consecutive match
- filenames: packed 2x128-bit names (when done=1, valid names shown in LSBs)
