Design a sequential Verilog module named 'fluttershy_scheduler' that computes the maximum number of customers Fluttershy can serve.

Module interface:
module fluttershy_scheduler(
  input clk,
  input rst_n,
  input start,
  output reg [2:0] max_customers,
  output reg done
);

Behavioral description:
The module implements a state machine to simulate clothing changes for serving customers. Parameters are hardcoded for N=4 customers and M=2 clothing types with the following scaled values:
- P_time[2] = {8'h0A, 8'h14} (put times 10, 20)
- R_time[2] = {8'h05, 8'h05} (remove times 5, 5)
- Customer data: {2'b10, 16'h0014}, {2'b01, 16'h001E}, {2'b01, 16'h0020}, {2'b10, 16'h0078} (customers at times 20, 30, 32, 120)

Logic operates as follows:
1. On start signal, initialize current_clothing = 0 (none), current_time = 0, count = 0
2. Check each customer sequentially at their arrival time
3. If clothing matches, increment count immediately
4. If doesn't match, check if there's enough time to remove current clothing + put required clothing
5. Transition through remove/put states with appropriate time delays
6. Update max_customers when all customers are processed

Timing: Computation completes in ≤ 16 clock cycles. Done signal asserts when result is valid. Use state machine with states: IDLE, CHECK, REMOVE_START, REMOVE_WAIT, PUT_START, PUT_WAIT, DONE.
