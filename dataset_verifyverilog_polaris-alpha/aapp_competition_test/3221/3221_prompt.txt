Design a sequential Verilog module named 'ginger_candy_optimizer' that finds minimal energy cycle in small road networks.

Module interface:
module ginger_candy_optimizer(
  input clk, // Clock signal
  input rst_n, // Active-low reset
  input start, // Start computation (pulse high)
  input [3:0] n_nodes, // Number of junctions (1-8)
  input [3:0] n_roads, // Number of roads (1-16)
  input [4:0] alpha, // Alpha parameter (1-20)
  input [7:0] road_data_valid, // Road data write enable (1 per cycle)
  input [2:0] u_in, // Junction u (3-bit)
  input [2:0] v_in, // Junction v (3-bit)
  input [15:0] c_in, // Candy count (16-bit)
  output reg [31:0] min_energy, // Computed L^2 + alpha*K (32-bit)
  output reg no_route, // High when no valid route
  output reg done // High when computation completed
);

Behavioral description:
1. Stores up to 16 roads (u, v, c) in edge list registers
2. Finds a cycle that:
   - Starts/ends at same junction
   - Uses each road exactly once
   - Minimizes energy = (max(c)^2) + (alpha * road_count)
3. Uses FSM with states: IDLE, LOAD_DATA, FIND_CYCLES, CALC_ENERGY, DONE
4. Implements cycle checking for connected graph with <=8 nodes and <=16 roads
5. Begins computation when 'start' is pulsed high after data loading
6. Output valid 1024 cycles after start assertion (fixed latency implementation)
7. If no valid cycle found, asserts no_route=1 and min_energy=0
Note: All roads must have unique candy counts (handled by testbench)
