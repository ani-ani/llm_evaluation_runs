Design a Verilog module named 'mirka_piano_solver' to find optimal K for multi-piano playback.

Inputs:
- clk: clock signal
- rst_n: active-low asynchronous reset
- start: pulse high to begin computation
- N [2:0]: number of multi-keys (2..8)
- a0, a1, a2, a3, a4, a5, a6, a7 [7:0]: signed 8-bit multi-keys (unused elements when N<8 ignored)

Outputs:
- done: high when computation complete
- max_correct [3:0]: max number of correctly played multi-keys (including first)
- best_K [7:0]: optimal non-negative K achieving max_correct (smallest if tie)

Behavior:
- Sequential module that tests all K from 0-255 upon start
- For each K, computes playback sequence and counts matches with input array
- First note always matches (counted in max_correct)
- Subsequent notes: new = prev + K (comp up), prev - K (comp down), prev (comp equal)
- Output valid when done=1 after latency of ~2048 cycles (256K * 8N worst-case)
- Use active-low reset to initialize all registers

Implementation notes:
- Use state machine: IDLE, INIT, EVAL_K_START, EVAL_NOTE, UPDATE_MAX, FINISH
- In EVAL_NOTE state: compare playback note with input array element
- Track current correct count per K and global max
- Signed 8-bit arithmetic for all computations
